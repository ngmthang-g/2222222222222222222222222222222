Many tabs reference those helpers instead of opening INI files independently.

This is a real shared service boundary.

## 2. Central config.ini path

Exact original documentation:
`Load central config from C:\Users\Admin\AppData\Roaming\TLMTool\config.ini.`

and:
`Save values to central config at C:\Users\Admin\AppData\Roaming\TLMTool\config.ini.`

The utility module also recovers:
- `getenv`
- `APPDATA`
- `TLMTool`
- `config.ini`.

Therefore the path is constructed from the current user's APPDATA location, not from the literal captured username in the compiled documentation.

Reconstruction contract:
`%APPDATA%\TLMTool\config.ini`.

## 3. Central config.ini parser/write behavior

Recovered:
- `configparser.RawConfigParser`
- UTF-8 read/write
- `has_section`
- `items`
- `add_section`
- `set`
- error logs for load/save
- `CONFIG_DIR.mkdir(parents=True, exist_ok=True)`.

The shared save helper writes values into a named section and creates that section when absent.

Unlike `settings.ini`, no temp-file/`os.replace` contract is recovered for this central `config.ini` path. Do not silently give both files the same write semantics.

## 4. Shared settings.ini safe-read contract

Exact original documentation:
`Read settings.ini safely. Use RawConfigParser (dup keys: last wins, no error).`

Recovered supporting constants:
- `RawConfigParser`
- `strict`
- `SETTINGS_PATH`
- control-character regex `[\x00-\x1f\x7f]`
- section enumeration.

Therefore the reader intentionally tolerates duplicate keys rather than failing as strict ConfigParser would.

A control-character sanitization path is present. Exact source-level scope of the sanitization pass is not fully readable, so E05 does not invent whether it applies to every value, every section name, or only malformed input lines.

## 5. settings.ini atomic-write and backup behavior

Exact original documentation:
`Atomic write settings.ini: temp file then os.replace.`

Recovered write machinery:
- `tempfile.mkstemp`
- suffix `.tmp`
- `fdopen`
- `replace`
- `strftime("%Y%m%d")`
- backup name fragments `settings.` + `.ini`
- `shutil.copy2`
- glob `settings.*.ini`
- `_BACKUP_KEEP`
- `sorted`
- `remove` / `unlink`.

This establishes:
1. a temporary file is written first;
2. final replacement is atomic via `os.replace`;
3. dated `settings.YYYYMMDD.ini`-style backup files exist;
4. older backups are pruned according to `_BACKUP_KEEP`.

The exact numeric value of `_BACKUP_KEEP` is not source-visible in readable constants and remains **UNKNOWN**.

## 6. Shared settings lock

A shared symbol `_settings_lock` is referenced throughout configuration-consuming tabs together with `read_settings`/`write_settings`.

This proves serialized/shared access is part of the config contract.

The exact concrete lock class/constructor is not source-visible in the readable constant evidence. E05 therefore records the presence of the shared lock and leaves its exact type **UNKNOWN**.

## 8. Typed reads/defaults remain tab-owned

Tabs use ConfigParser typed getters where appropriate:
- `getint`
- `getboolean`
- string/JSON parse paths
- fallback/default literals local to the feature.

Example from Start:
- grid columns/rows use integer reads;
- detached auto-open uses boolean read;
- detached grid uses its own stored value.

The shared helper owns safe file access; the tab owns how each key is interpreted and what fallback it uses.

Reconstruction must not move all typed defaults into one global schema unless later evidence explicitly supports that.

## 9. JSON-in-INI pattern

Several complex settings are stored as serialized JSON strings inside the shared INI, evidenced by:
- `json.loads`
- `json.dumps`
- `ensure_ascii`
near Party/Phó Bản/Tối ưu configuration keys.

Therefore the original design is mixed:
- scalar INI values for simple state;
- JSON-encoded strings for complex rows/groups/schedules.

Do not normalize these to a new JSON file during parity reconstruction.

## 10. Save-on-destroy / debounced save ownership

Feature modules expose patterns such as:
- `_save_on_destroy`
- `_schedule_save`
- config variable change callbacks.

Examples:
- Login has `_schedule_save`, `_save_accounts`, `_save_config`;
- Farm/Train LSV/Phó Bản/Rao/Tối ưu have save-on-destroy or config-change save paths.

This means persistence is not only a single application-exit dump. Tabs can persist state during interaction or on their own destruction lifecycle.

Exact debounce durations are feature-specific and deferred to the relevant feature gates unless directly needed there.

## 11. InfoTab has a second config.ini contract

`TLMInfoTab` separately recovers:
- `_get_config_path`
- exact filename `config.ini`
- doc: `Return config.ini path alongside this script.`
- `ConfigParser`
- doc: `Load config.ini as a simple dict.`
- doc: `Save config dict back to config.ini.`
- `read_dict`
- `Info`.

This must remain distinct from the shared central APPDATA config helper.

D06 already recorded both path contexts. E05 confirms the parser contracts differ:
- shared central config uses `RawConfigParser` and section/value helpers;
- InfoTab uses its own simple-dict ConfigParser path.

Whether both resolve to the same physical file in every frozen/runtime packaging context is **not assumed**.

## 12. Runtime state files are not settings.ini

The following remain separate state stores and are not absorbed into E05's shared INI:
- `login_online.json`
- `last_login_times.json`
- `forwarder*.txt/json`
- `proxy*.txt/lock`
- `/sdcard/TLM/tlm_*.json`
- logs.

This ownership boundary is inherited from D06/E04.

## 13. Reload/propagation model

No evidence supports one global hot-reload event that reparses every tab whenever settings.ini changes.

Instead, recovered behavior is:
- each tab loads its own keys through its `_load_config`;
- each tab writes through shared helpers;
- selected/rebuilt tabs and lifecycle callbacks reload or reapply their own state;
- plan/permission updates are a separate service path, not a config-file reload path.

Therefore E05 does not invent a central filesystem watcher.

## 14. Reconstruction contract

For parity:
1. keep central path helpers in the shared utility layer;
2. use `%APPDATA%\TLMTool` for shared config/settings paths;
3. use RawConfigParser safe duplicate-tolerant settings reads;
4. keep a shared settings lock;
5. write settings atomically through temp file + replace;
6. preserve dated backup/pruning behavior;
7. preserve the common `[Settings]` section and original key names;
8. preserve per-tab typed defaults/fallbacks;
9. preserve JSON-in-INI for complex feature rows;
10. preserve InfoTab's separate config.ini contract;
11. keep runtime JSON/text state files separate;
12. do not invent a global hot-reload watcher.
