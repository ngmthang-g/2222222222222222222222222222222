## Confirmed defects and scoped fix
1. **Post-join restart race:** Old `stop()` captured the old worker and waited `join(timeout)` outside the state lock. Another thread could `start()` during the tiny gap between completed old join and cleanup, install a new `_clock/_thread`, and the old stop would disable the newly started clock while leaving its worker alive. **Fix:** new dedicated `_lifecycle_lock` held for the full stop/join/cleanup transaction; `start()` attempts non-blocking acquisition and refuses during pending stop. This is a S43 safety correction, not a claim of original instruction parity.
2. **Hung clock blocked stop timeout:** Old `poll_once()` called untrusted `now()` holding `_lock`, and `stop()` tried acquiring that lock before setting cancellation. A stalled `now()` made `stop(timeout=...)` wait indefinitely. **Fix:** set `Event` under lifecycle mutex **without acquiring poll lock**, join only for bounded timeout, return `False`/STOPPING without blocking on a hung provider, refuse restart while old worker is alive. On subsequent release, stop joins and cleans.
3. **Late event after cancellation:** A stalled `now()` could unblock *after* stop set Event and then still append blocked due events. **Fix:** recheck `_cancel.is_set()` / `_closed` after `now()` and `clock.poll` inside `poll_once()`, discarding late observations. Avoid lock-bound read-only status/active/thread_alive getters while clock provider holds poll lock.
