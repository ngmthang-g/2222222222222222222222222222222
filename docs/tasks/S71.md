## STATUS

## Specific source-confirmed defect
Read LIVE PLAN.md and STATE.md S70 NEXT_ACTION, confirmed this S71 document initially absent. Original C14/C03/S11 supports DwmUnregisterThumbnail / DestroyWindow cleanup. In the reconstructed S11 `ReadOnlyDwmPreviews.clear`, a native DWM unregister exception from the first thumbnail previously escaped immediately, leaving other active source slots undisturbed. `shutdown` marked the controller CLOSED before clear, making a later retry ineffective; a S70 `C14DetachedHost.close` session-shutdown exception also prevented Tk owner destroy. These are directly identified **reconstruction safety defects**, not a source-level assertion about recovered Nuitka error handling.

## Surgical repair
- EXISTING `src/dwm_preview.py`: `ReadOnlyDwmPreviews.clear` now attempts `_remove` for ALL slots even when an earlier `unregister` or `destroy_destination` raises; the FIRST native error is re-raised AFTER all attempts. Existing `_remove` uses try/finally to attempt destroy even when unregister fails. Failures are not falsely reported as successful cleanup. All source HWND/PID validation, DWM registration and owner/placement semantics unchanged.
- EXISTING `src/detached_host.py`: `close` always attempts S68 session shutdown then Tk host destroy and clears local owner/session refs, even when DWM cleanup raises. Returns explicit `HOST_CLOSED_NATIVE_CLEANUP_FAILED` instead of lying about perfect native teardown. `shutdown` marks permanently CLOSED even if earlier cleanup reports failure, with explicit `CLOSED_NATIVE_CLEANUP_FAILED`. This does NOT claim every native handle was successfully released when a real Win32/DWM API fails. Tk owner-thread gating unchanged.
- No previous source module modified beyond these two narrow safety paths; no fake Tách rời UI, guess of original detached spacing, game input or Proxy.
