# C19 — Đồng bộ phím chuột

## STATUS
**VERIFIED_WITH_EXPLICIT_PAYLOAD_AND_STARTUP_TIMING_UNKNOWNS**

C19 recovers the input-synchronization subsystem from the original TLMTool 2.1.2 inner EXE. This is separate from C18 layout synchronization.

## 1. Real UI control and runtime state
Original Xếp-lưới UI recovers:
- visible button: `Đồng bộ phím chuột`
- callback: `_toggle_input`.

Original runtime state recovers:
- `input_active`
- `_sync_keepalive_id`
- `_sync_locked`
- `_sync_locked_guard`.

The control is a real persistent input-sync state, not a one-shot click action.

## 2. Master is the input source
C05 already proved master HWND is the synchronization source.

Original listeners recover:
- `mouse.Listener` with `_on_master_click`, `_on_master_scroll`, `_on_master_move`;
- `keyboard.Listener` with `_on_master_key_press`, `_on_master_key_release`.

Thus mouse and keyboard events originate from the selected master and are replicated toward slave game HWNDs.

## 3. Mouse click path resolves master client coordinates
Recovered APIs/state include:
- `WindowFromPoint`
- `GetAncestor`
- `ScreenToClient`
- mouse buttons `left`, `right`, `middle`.

The click handler converts the captured screen point into master client coordinates before generating slave-target coordinates.

## 4. Coordinate scaling is size-aware
Exact original documentation:
`Chuyển client coord của master sang slave theo tỷ lệ kích thước cửa sổ.`

The same doc explains that different client sizes are handled by scaling coordinates so the corresponding relative point is targeted on each slave.

Recovered supporting APIs/state:
- `GetClientRect`
- master/slave size fields
- scaled coordinate log fields.

Therefore C19 must not mirror raw absolute pixels when game client sizes differ.

## 5. Click synchronization is serialized through a worker
Recovered methods:
- `_sync_worker`
- `_do_down`
- `_do_up`
- queue `put` / `task_done`.

Original documentation fragments state that click sync is handled sequentially so press/release ordering is preserved and race conditions are avoided.

Thus click down/up must remain ordered; it is not safe to fire independent unsynchronized threads for press and release.

## 6. Slave input block/unblock lifecycle
Recovered methods/state:
- `_sync_block_slave`
- `_sync_unblock_slave`
- `_dll_mark_blocked`
- `_dll_restore_window`
- `SendMessageTimeout`
- `SMTO_ABORTIFHUNG`.

Exact original block documentation begins:
`Block input 1 slave (activate + lock).`

Recovered comments further show:
- operation is idempotent;
- hung windows should not block the worker;
- short retry behavior exists, including a documented `retry ngắn 2 lần` path when Unity is temporarily busy.

Exact retry delay and every return-code branch are not fully source-visible and remain UNKNOWN.

## 7. Keepalive is exactly 1.5 seconds
Exact original documentation:
`Re-block slaves mỗi 1.5s — cửa sổ mới được block, phòng bị unblock.`

Method:
- `_sync_keepalive`.

This cadence belongs only to input synchronization and must not be copied into C18 layout-worker timing.

## 8. Watchdog unlock prevents stuck slaves
Recovered method:
- `_watchdog_unlock`.

Exact original documentation:
`Mở khóa slave block quá 10s (mất release — master đóng/đổi/thoát).`

Therefore stale slave-lock state is automatically released after roughly 10 seconds when a matching release can no longer arrive because the master closed, changed, or the app exited.

## 9. Mouse wheel and move have dedicated paths
Exact original docs:
- `Handle mouse wheel scroll from master and sync to slaves.`
- `Handle mouse move from master and sync to slaves (throttled).`

Recovered state/API:
- `send_scroll`
- `ClientToScreen`
- `_last_move_time`
- `send_move_slave`.

Thus scroll and move are not implemented by replaying normal clicks. Mouse move has an explicit throttle layer.

Exact throttle interval is not source-visible in current readable constants.

## 10. Keyboard path
Recovered keyboard-side fields:
- `_on_master_key_press`
- `_on_master_key_release`
- `GetForegroundWindow`
- `vk`
- `WM_MY_SYNC_KEY`.

This proves keyboard events are translated to a virtual-key representation and propagated through the tool's dedicated synchronization message path.

Exact custom-message payload fields/bit packing are not recoverable from readable static constants and remain explicit UNKNOWN.

## 11. Master-change safety
C05 exact behavior remains authoritative:
- when the user selects another master while input sync is ON, input sync automatically turns OFF;
- all slave locks are released;
- user must enable input sync again after selecting the new master.

This safety rule is specific to input sync and must be preserved.

## 12. Limit and mode integration
C08/C18 already proved:
- selecting Xếp-lưới/internal `sync` automatically enables input sync;
- switching to Auto/manual disables it;
- over the runtime max-window limit, `_auto_stop_sync` shuts down both layout and input synchronization.
