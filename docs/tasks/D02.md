## 1. Evidence policy

D02 does **not** convert string adjacency into a claimed Python `import` statement.

For each TLM internal module with an exact compiled module marker, D02 defines its compiled constant/string block up to the next valid module marker. Inside that block it records a relationship only when a tagged string resolves exactly to a D01 accepted module/reference name.

Relationship status:
`STATIC_REFERENCE_NOT_IMPORT_PROOF`

This proves that the compiled module block contains a reference to that module name. It may represent an import, injected/shared object, runtime module lookup, typed/helper reference, or another dependency mechanism. Exact Python import syntax remains UNKNOWN unless stronger evidence appears later.

## 9. What D02 does NOT claim

D02 does not claim:
- that all 377 edges are literal Python import statements;
- exact import syntax or alias names;
- import execution order;
- conditional-vs-unconditional import behavior;
- outgoing relationships for the five TLM names lacking exact module markers;
- call direction merely from a reverse reference.

These boundaries are intentional and prevent a false dependency graph.
