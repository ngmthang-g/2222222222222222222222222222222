## 1. Farm rows are HWND rows with a bound PID snapshot

`FarmTab._add_or_update_row` starts from:
- `hwnd`
- current PID through `_pid_of`
- `bind_window_identity`
- `unbind_window_identity`.

The frozen mismatch log is explicit:

`[Farm] hwnd=<...> đổi process (pid <old> → <new>) — cửa sổ cũ đã mất, tạo lại row mới`

Therefore HWND alone is not the account identity.

A row is the pair:
- current top-level game HWND;
- PID snapshot bound when that row was created.

If Windows later reuses the same numeric HWND for another process, Farm destroys the old row identity and recreates it rather than silently assigning the old runtime state to the new process.

## 2. _hwnd_alive is the runtime ownership guard

Exact original documentation:

`Check hwnd còn mở, đúng process đã bind, và visible.

expected_pid: pid snapshot lúc tạo row — lệch là HWND bị tái sử dụng
bởi cửa sổ khác → False. None → hành vi cũ, giữ tương thích test/fake.`

The check therefore requires:
- `IsWindow(hwnd)`;
- `IsWindowVisible(hwnd)`;
- current PID still equals the row's expected PID when an expected PID exists.

This guard is used by Farm lifecycle workers and prevents stale work from acting on a reused HWND.

## 3. Incremental refresh updates existing rows; it does not rebuild the table

Exact `_add_or_update_row` documentation:

`Add row mới nếu chưa có, update tên nếu đã có. Giữ nguyên map/x/y.

ci: character info đọc sẵn từ background thread (tránh đọc memory
trên main thread). None → tự đọc (fallback).
bag_slots: số ô túi đồ (Site 10) đọc sẵn từ background thread.
None → giữ giá trị cũ (đọc lỗi).`

This locks several behaviors:
- first sight of an HWND creates one row;
- later refreshes update that row in place;
- Sell/Train coordinate choices are preserved rather than reset;
- background-pre-read character info is preferred;
- background-pre-read bag-slot count is preferred;
- bag read failure keeps the old displayed value.

## 4. Exact refresh ownership and cadence

Đọc window list + char info (memory read — chậm) trong BACKGROUND thread,

The active flow is:

→ next scheduled refresh.

Thus account discovery, RoleName/MapID/bag memory reads do not normally block Tk.

## 23. _gen is the stale-worker generation guard
