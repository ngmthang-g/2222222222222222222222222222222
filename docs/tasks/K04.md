## 1. Normal NPC return target is exact

Exact `_punish_goto_bodau` documentation says:

`Move về bổ đầu Tô Châu (map 4, tile 224, 285).`

The function's frozen contract also locks:
- target map = **4**
- target tile = **(224, 285)**
- arrival tolerance = **96**
- tag/state text = `Về bổ đầu`
- movement waits for arrival and accepts a stop predicate.

The tolerance is deliberately larger than the older value 48 because the NPC area is crowded/collision-prone.

## 2. Re-inject is attempted before normal move, but injection failure is fail-open

Exact `_punish_goto_bodau` prose says it **re-injects DLL before move** because the hook can be lost after respawn/restart.

Exact error surfaces:
- `inject cho move thất bại, thử di chuyển trực tiếp`
- `inject lỗi:`.

Therefore injection is a repair attempt, not a hard gate:
- injection success → normal movement;
- injection false/exception → log, then still attempt direct movement.

Do not turn injection failure into an immediate Trừng Ác account stop.

## 3. Normal movement failure is current-cycle skip, not terminal account completion

Exact movement outcomes:
- stop during move → `move bổ đầu bị stop (...)`
- fail/timeout → `move về bổ đầu thất bại → skip vòng`
- successful move but wrong map → `sai map sau move (map=...)`.

Frozen doc explicitly says fail/timeout:
- call `stop_character`;
- return False;
- caller **SKIP vòng**;
- avoid clicking NPC from the wrong place.

After a nominal arrival, MapID is checked to be **4**.

Thus:
- movement failure/wrong-map = fail-soft for the open-ended Trừng Ác session;
- 30/30 is the later terminal-per-account condition, not move failure.

## 4. Teleport mode has a pre-step but still converges on the same final NPC move

Strong static contract:

The exact UI element represented by (490,429) is not text-labelled in the frozen constants and is not invented here.

Horse mode does not require this teleport pre-step.

## 9. Full-dialog acknowledgement is internal memory UI and verifies closure

When full is detected, the helper calls:

`click_dialog_button`

for `Ta biết rồi`.

The same frozen `memory_items` module documents that this helper:
- finds the GameDialog button by text;
- calls `GameDialog:FunctionButtonClicked` internally;
- lets the game send its normal dialog packet/close action;
- returns True only when the dialog is confirmed closed.

Therefore the 30/30 acknowledgement is not a blind screen-coordinate click.

## 10. Full-check failure modes are deliberately fail-open as “not full”

Exact helper outcomes:
- dialog read exception → `đọc bảng Full lỗi:` → False
- no matching dialog → `không thấy bảng Full → coi như chưa đầy` → False
- button click failure → `bấm '...' thất bại → coi như chưa đầy` → False
- button-click exception → `bấm nút Full lỗi:` → False
- successful detect + close → True.

This means inability to prove the limit does **not** terminal-stop the account.

## 12. Stuck/no-target cancellation uses a completely different NPC path

When target coordinates cannot be extracted, the frozen target region logs:

`_punish_cancel_quest`.

The cancellation helper's exact doc is:

1. click **(1072,130)** to close the current panel;
2. `move_to_npc(map 4, npc 698)`;
3. click **(479,480)** then **(476,422)** to cancel the quest;
4. caller skips the current cycle and the next outer cycle starts again from the beginning.

This is recovery, not a terminal account stop.

## 13. Shared move_to_npc gives cancellation a verified-dialog NPC arrival

The exact shared `memory_items.move_to_npc` documentation says:
- get NPC position;
- `move_character` to it;
- `ClickNPC`;
- verify GameDialog opened;
- if the NPC is on another map or has no live position, fall back to the game's NPC navigation;
- return True when dialog opens.

Therefore the cancellation path's NPC 698 step is not merely a fixed screen click.

This shared-helper evidence is included only because `_punish_cancel_quest` directly invokes it.

## 14. Cancellation helper failure is fail-soft to the next Trừng Ác cycle

Exact cancellation errors:
- `tới NPC hủy NV lỗi:`
- `không mở được hội thoại NPC hủy NV`.

`đã gửi hủy nhiệm vụ → sang vòng mới`.

The no-target caller already classifies the current execution as a skip/retry cycle. There is no terminal-account message or activity-wide cancel in the cancellation helper block.

Strongest static contract:
- successful cancel → skip current cycle, restart from quest phase next outer iteration;
- cancel failure → log; the current target step still fails/skips rather than killing the entire Trừng Ác session.

The exact return Boolean on each internal helper exception is not separately instruction-bound, but no hard-stop surface is recovered.
