## Actual original-backed defect
Resumed LIVE PLAN.md, STATE.md S76 verified NEXT_ACTION and E08 original evidence. E08 confirms that normal TLMTool close routes through each Tk tab's own Destroy/save/stop handler; normal app exit is NOT the Info forced os._exit, updater, Start Reload or process-kill path. C15 says native DWM previews are owned by the Start view and must release their preview HWNDs on teardown.

Current src/start_tab.py S76 already **correctly** latches uncertain native DWM cleanup. However, S76 did not cover E08 tab exit:
- _stop_refresh first stopped layout workers, timers and the S09 Start poller; then called _drop_previews directly. A DWM shutdown exception stopped the method BEFORE _sync_tiles(()) / read-only CLOSED status; switching tabs could raise instead of finishing.
- shutdown set _closed=True and stopped some workers, then _drop_previews. Any native exception escaped BEFORE every registered Tk root handler was unbound and BEFORE poller.shutdown(); other owners might remain alive. This is a **local, reproducible** bug, not an assertion about original Nuitka exception-handling implementation.

## Narrow source patch
ONLY the existing src/start_tab.py changed (commit **2f1b5a03d2f49e9c3078b1a208e8f14729aaf1a7**). No old S76 preview teardown semantics, source-baseline screenshot, signed Info, game actions or GUI controls changed.

- _stop_refresh catches only the native DWM owner failure from _drop_previews after already stopping workers/poller, retains sticky _preview_cleanup_faulted and proceeds to clear old item UI, render STOPPED and expose the explicit "Preview lỗi: giải phóng DWM chưa xác minh". A later Start selection cannot create new DWM while the fault remains latched.
- shutdown sets _closed first to fence late Tk work, then attempts **every** independent owner teardown: C07 reset cancellation, C10/C11 stack cancellation, C18 sync shutdown, preview maintenance shutdown, native DWM controller shutdown, Tk registered parent handler unbind, and the S09 poller shutdown. It reports the FIRST exception **after** all other teardown attempts, never reports complete clean shutdown when native release is unverified.
- The original exact Tk child Destroy order remains unknown; this is a local bounded safety fix, not a process-wide game/window kill or reset.
