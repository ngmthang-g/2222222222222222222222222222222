## Staged implementation

1. **NEW `src/login_independent_window_activation.py`**: `activate_verified_launched_game(process, hwnd)` requires a **retained actually launched Popen handle** with positive PID that has NOT exited, exact one visible top-level HWND bound to that PID, current actual game-exe candidate, and S78's existing native `NativeDwmBackend.source_matches` guard. A user-triggered native restore/show/foreground attempt is made ONLY after all these checks; returns `OS_FOREGROUND_ACCEPTED_NOT_LOGIN` / `OS_FOREGROUND_REFUSED` / stale or exited status; no keyboard/mouse/game packets, no synthetic HWND/title-to-RoleName.
2. **UPDATED `src/login_independent_game_launcher.py`**: stores at most one `Popen` handle and corresponding verified HWND for the most recently launched game; clears prior selection on each new explicit game launch, drops stale identity after failure and on shutdown. The retained process handle prevents unsafe trust in a recycled bare PID. Exposes `can_activate_last_window` and user-triggered `activate_last_window`; native worker and game process are never killed on tab close.
3. **UPDATED `src/login_independent_tab.py`**: independent-only user-click **“Đến game”** control next to original F01 “Mở game”. It stays disabled until S188 actually returned a verified PID/HWND for a tool-launched, still live process; on user click revalidates and asks Windows to restore/foreground that window. Clear failure messages, no false login-status claim; truncated compact status has a user-clickable full diagnostic display. Historic `src/login_tab.py` and original 2.1.2 UX/binary untouched.

## Honest limitations

- “Đến game” is a locally added **independent usability action** following documented original C03 semantics, NOT an original F01 pixel-identical third button. UI parity for this addition must be evaluated during consolidated test; it intentionally does not replace F05 injection and may not work if game cannot start normally on user's install.
- A successful Win32 `SetForegroundWindow` request is **not proof** of in-game login, role name, HP, captcha or game screen readiness. The OS can also deny focus for foreground security rules; the tool reports refusal without faking success.
- No original permission/heartbeat, no signed Info requirement, DLL inject or Proxy, no client memory reads. Access restricted to a live, **own-launched** retained OS process and its rechecked HWND; existing Start tab handles game windows that were opened outside this launcher.
- No static recompilation, unit/native/Win64 GUI/game or packaged EXE test performed by explicit owner request. This code is `SOURCE_IMPLEMENTED_UNTESTED`, NOT validated or guaranteed to work.
