## 1. emu_client.js — resident Frida RPC memory reader

`emu_client.js` is a compact **150-line Frida 17 resident script** intended for `emu_reader.py`.

Exact `rpc.exports` surface:
- `ping()`
- `setBase(addrStr)`
- `readAll()`
- `validate(expectedRid)`
- `scanRoleId(rid)`
- `scanShape()`
- `bagSlots()`.

The architecture is:

```text
PC emu_reader
  ↓ Frida client/session
guest frida-server
  ↓ inject resident JS
emu_client.js
  ↓ rpc.exports
memory scan/read inside Android game process
```

## 2. emu_client role-structure validation

The script validates a candidate player structure with strict fields/constraints:
- RoleID @ `+0x10`
- Sex @ `+0x20`
- FactionID @ `+0x24`
- Level @ `+0x28`
- MapID @ `+0x50`
- PosX / PosY @ `+0x54/+0x58`
- Exp / MaxExp @ `+0x60/+0x68`
- PKMode @ `+0x70`
- Money / BoundMoney @ `+0x78/+0x7C`
- CurrentHP / MaxHP @ `+0xA4/+0xA8`
- CurrentMP / MaxMP @ `+0xAC/+0xB0`
- Rage / MaxRage @ `+0xB4/+0xB8`
- ServerID @ `+0xF8`
- IsGM @ `+0xFC`
- MoveSpeed @ `+0x100`
- IsRiding @ `+0x108`.

Validation includes exact `MaxRage == 1000`, sane map/level/position/rage/faction ranges, RoleID > 100000, and readable UTF-16 RoleName.

Discovery methods:
- targeted RoleID scan: search little-endian RoleID and subtract `0x10`;
- blind shape scan: search `e8 03 00 00` (1000 / MaxRage) and subtract `0xB8`;
- writable-range enumeration via Frida `Process.enumerateRanges({ protection: 'rw-' ...})`.

## 3. emu_client bag contract

`bagSlots()` reads:
- player + `0xC8` dictionary pointer;
- entries pointer at dict + `0x18`;
- count at dict + `0x20`;
- entry stride 24 bytes;
- item value pointer at entry + 16;
- item ID at value + `0x14`;
- item site at value + `0x1C`.

Only `Site == 10` entries with plausible item IDs are counted.

This directly links the emulator helper to the same bag semantics documented by the PC memory subsystem.

## 4. ld_remote.js — AutoX floating emulator UI

`ld_remote.js` is a **1,297-line AutoX/Auto.js floaty UI**.

It is not the memory scanner. Its role is the guest-side user interface / command client for the PC listener.

Core identity/network behavior:
- static token default: `tlm`;
- default PC base: `http://172.16.1.2:8765`;
- fallback candidate: `http://10.0.2.2:8765`;
- PC may inject a LAN URL by replacing `__PC_BASE__`;
- emulator identity is derived primarily from its guest IPv4 because cloned LDPlayer instances may share serial/android_id;
- successful PC base is cached in AutoX storage `tlm_tool`.

Host selection is parallelized because dead routes can hang despite timeout behavior.

## 5. ld_remote HTTP client endpoints

Every POST helper injects:

Listener evidence:

- token from JSON or query string compared with `[Emu] remote_token`, default `tlm`.

## 6. PC→emulator action protocol

`ld_remote.js` sends structured action requests.

### Step runner
`POST /emu_steps` payload contains a JSON-serialized list of steps plus a gap.

PC-side accepted step types include:
- `tap`
- `text`
- `key`
- `wait`.

Recognized key examples include ENTER/RETURN, BACK and HOME.

### High-level action
`POST /emu_act {act: ...}` supports at least:
- `to_train`
- `sell`
- `heal`.

PC `emu_remote` resolves configured presets and then runs the action on the identified emulator.

### Farm toggle
`POST /emu_farm_toggle` toggles farm state. The original PC-side documentation explicitly says this is still a stub/phase state acknowledgement where the actual farm engine is not yet fully connected. D07 preserves that limitation.

## 7. Local/ADB configuration bridge

The overlay caches config locally and also writes:

`/sdcard/TLM/tlm_<aid8>.json`

with:
- `aid`
- `updated`
- `coords`
- `cfg`.

The PC can pull this file through ADB without requiring the HTTP listener.

Overlay config keys include:
- `town_condition`
- `town_method`
- `heal_preset`
- `sell_preset`
- `train_preset`
- `respawn_fast`
- `auto_reconnect`
- `pickup_no_cankhon`
- `trist`
- `buff_0`, `buff_1`, `buff_2`.

Config changes are auto-saved after a short debounce; the UI also keeps a 1-second countdown refresh for buff timers.

## 8. PC emulator manager boundary

Original EXE strings document:
- guest `frida-server` under `/data/local/tmp/frida-server`;
- automatic ensure/push/chmod/start behavior;
- `emu_client.js` resident RPC architecture;
- ADB reading of `/sdcard/TLM/tlm_*.json`;
- `ld_remote.js` deployment into AutoX-visible script directories;
- replacement of `__PC_BASE__` with the PC LAN URL;
- overlay permission/app launch guidance.

The PC listener identifies the calling emulator by socket peer IP and explicitly avoids guessing when multiple cloned emulators share Android identifiers.

## 9. forwarder.exe

`forwarder.exe` is a separate x64 Nuitka-built helper with a SOCKS proxy-forwarding role.

Recovered static strings include:
- `SOCKS5 Forwarder`
- SOCKS5 / SOCKS4 / HTTP CONNECT paths
- `LISTEN_HOST`, `LISTEN_PORT`
- local `127.0.0.1`
- `forwarder_mode.txt`
- `forwarder_targets.txt`
- `forwarder_pinned_proxy.txt`
- `proxy_alloc.txt`
- `proxy_bad.txt`
- target/proxy selection, bad-proxy cooldown and pinned-proxy logic.

Its manifest requests administrator privileges.

D06 already established that `Default.ppx` sends the game through local SOCKS5 `127.0.0.1:10800`. D07 records that this template and the forwarder architecture are paired, but does not invent an exact `LISTEN_PORT` constant from the forwarder binary unless directly source-visible.

## 10. bootstrap/update/7z/Proxifier helper boundary

These helpers were already substantially covered by Gate A, so D07 only records the material connection:

### bootstrap.exe
- AutoHotkey executable;
- accepts two arguments: new file + target file;
- sleeps, replaces target with new file;
- used by updater to replace `update.exe` safely.

### update.exe
- AutoHotkey updater, `UpdaterVersion := "1.2"`;
- downloads update ZIP from Pixeldrain or Google Drive;
- uses packaged `tools/7z.exe` when available;
- replaces `TLMTool.dist` contents;
- delegates updater-self replacement to `bootstrap.exe`;
- relaunches `TLMTool.exe`.

### tools/7z.exe
- bundled 7-Zip CLI extraction helper.

### ppx/ProxifierSetup.exe
- third-party 32-bit Proxifier installer;
- paired with `Default.ppx` profile setup.

D07 does not reopen Gate-A launcher/updater reconstruction beyond these confirmed connections.

## 11. Security/trust boundary relevant to parity

The emulator remote listener is network-reachable on `0.0.0.0:8765` and uses the configured token, default `tlm`.

This is part of the original behavior contract. A parity reconstruction must preserve the protocol semantics first; any hardening or default-token change would be a later explicit change, not a silent parity modification.
