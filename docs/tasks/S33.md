## 2. Implementation — new `src/adb_serial_epochs.py`
- Pure OFFLINE/non-authoritative `advance_serial_epochs(previous, current, observed_reboots=())` wraps **existing S32 TimedAdbIdentity** and accepts only already-captured S31 transport states with independently supplied hint timestamps.
- Immutable `SerialEpochSnapshot` records each serial's last state, **online-epoch boundary**, generation number and `EpochEvent` evidence. Inputs and event maps are copied into read-only mappings; no new native Windows or ADB interface.
- On first observed ONLINE serial: locally create a new boundary at the capture's monotonic timestamp; hints recorded **at or before** the boundary are rejected, even if S32's per-field 30-second TTL otherwise says fresh. Requires a subsequent capture containing a genuinely later-observed hint. This strict comparison is **S33 conservative local choice**, not proven original source micro-timing.
- On observed ONLINE→OFFLINE/UNAUTHORIZED/ABSENT: clear the online epoch; when the serial returns online, increment generation and create a new boundary. An explicitly caller-supplied reboot marker also creates a new epoch even while the serial string is unchanged. This marker is **not produced or authenticated by this tool**. Unknown/duplicated/bad markers and invalid/duplicate ADB captures cause fail-closed statuses.
- When capture times regress or repeat, mark non-increasing chronology, deny history. When previous capture is invalid or the gap exceeds S31's locally chosen **30s** transport freshness limit, discard old epochs and establish fresh baseline, not a presumed uninterrupted session.
- `SerialEpochSnapshot.assess(serial,field,now)` delegates to **S32** for field/transport TTL and applies the epoch boundary. `unique_serial_for` requires all online peers' hints for the identity field to be individually fresh and newer than each peer's current epoch boundary; duplicate aid/hwid/IP remains ambiguous. A matching Android ID across serials **never automatically rebinds** an account or command target.
- `emulator_account_count=None`, `combined_running_count=None`, `is_authoritative_account_total=False` always. Any S26 launch attempt driven by S33 partial evidence is denied `RUNNING_WINDOW_COUNT_UNKNOWN`.
- There are NO ADB commands, adb server start, Frida attachment, VM/game process execution, DLL loading/injection, new UI buttons, network requests or Proxy runtime. Nothing in S01–S32 original working source was modified.
