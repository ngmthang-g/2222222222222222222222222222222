## 3. UI dispatch is explicitly background + daemon

Immediately after the all-account button construction, the frozen `_build_ui` constant surface contains, contiguously:

- `threading`
- `Thread`
- `target`
- `daemon`
- `start`
- `_goto_sell_all`
- `_sell_all`
- `_move_all`
- `_farm_all`.

This binds the four visible commands to background `threading.Thread(..., daemon=True).start()` dispatch rather than running the all-account worker synchronously on Tk.

Therefore the **Tk click path is fire-and-forget with respect to the outer worker**:
- the UI callback starts the worker;
- Tk is not meant to wait for the complete multi-account operation.

This does **not** by itself prove whether an all-account worker later joins its own child threads. That inner completion policy is treated separately below.
