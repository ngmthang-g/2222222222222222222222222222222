## 1. _checked_rows means every TrainLSV account row

Exact frozen documentation:

"Tất cả acc trong danh sách (thao tác hàng loạt áp dụng cho mọi acc)."

There is no per-row selection checkbox in B06 or the row builder.

Therefore the old method name _checked_rows and old docs saying "được tick" are stale terminology. For TrainLSV bulk actions, the target set is the complete current account-row list.

The log "Không có acc nào được chọn" must therefore be understood as the bulk target list being empty, not as all checkboxes being unchecked.

## 2. Visible bulk-action bar and outer Tk-thread handoff

B06 and frozen UI wiring agree on exactly four visible commands:

- Tới LSV -> _move_lsv_all

The _build_ui constant surface directly contains threading.Thread, target, daemon and start beside those four methods.

## 4. Bulk "Đánh" is not the full TrainLSV automation FSM

Per-account manual helper _farm_acc has exact documentation:

Therefore the visible all-account Đánh command is a manual one-shot memory/internal StartAutoFight operation through _farm_all -> _farm_acc.

It is NOT equivalent to the large Bắt đầu button and does not start the complete TrainLSV _farm_cycle.

## 5. Manual Fight refuses to overlap an already automated Farm account

Immediately before _farm_acc's StartAutoFight block, the frozen module references _is_acc_farming and exact text:

"[Đánh] hwnd=... đang farm tự động -> bỏ qua thao tác thủ công (dừng farm acc trước)"

This skip is independently proven for _farm_acc/_farm_all.

No equivalent active-Farm skip rule is independently recovered for _move_lsv_all, _move_all or _leave_lsv_all. Do not copy ordinary Train H13 conflict behavior into those commands by analogy.

## 6. _stop_acc is cooperative per-account stop

Exact frozen documentation:

"Dừng nhân vật + tắt flag farm cá nhân."

So stopping a TrainLSV account:

The worker is allowed to observe the stop condition and exit through its cooperative checks.

## 14. Stop is joined/drained, not thread-killed

The module directly contains join and _wait_farm_stop.

Recovered local model for _wait_farm_stop:

self, threads, has_remaining, wt.

Exact documentation:

"Chờ farm thread thoát (sau khi hoàn tất sub-cycle hiện tại).

has_remaining=True (còn acc khác vẫn farm): chỉ bỏ thread đã dừng khỏi tập,
nút giữ trạng thái Dừng Farm.
has_remaining=False (dừng hết): reset nút về Bắt đầu."

Exact outcomes:
- partial stop -> "Dừng xong phần acc được chọn — các acc còn lại tiếp tục"
- full stop -> "Đã dừng hoàn toàn"
- full stop resets Bắt đầu / #388e3c / normal.

So TrainLSV stop is cooperative:
1. mark target session stopped / invalidate its generation;
2. current sub-action sees _check_stop;
3. worker exits;
4. wait path joins/drains the worker;
5. UI is finalized only after worker termination.

Exact join timeout/blocking microbehavior remains UNKNOWN.

## 15. Stopping the last individual account becomes global-stopped state
