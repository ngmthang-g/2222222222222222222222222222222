# E03 — Tab loader / create_tabs lifecycle

## STATUS
**VERIFIED_WITH_CONDITIONAL_VISIBILITY_AND_LAZY_BUILD_MODEL**

E03 recovers how the main Notebook creates tab frames, defers/constructs tab content, applies visibility/permission gates, and coordinates tab refresh.

The original EXE is primary evidence; Gate-B screenshots remain the visible production-tab baseline.

## 1. Internal tab-frame creation helper

`TLMMainApp.create_tabs` contains local helper:

`TLMMainApp.create_tabs.<locals>._new_tab`

and state maps:
- `_tab_inner`
- `_tab_frames`
- `_tab_keys`.

The helper creates Notebook frames and can:
- add them in a specific insertion order;
- start tabs in `hidden` state;
- optionally wrap a frame in a scrollable Canvas/Scrollbar container.

## 4. Initial hidden-state model

The create-tabs constant block repeatedly associates the action-tab frame creation calls with `hidden`.

The Info tab call is distinct and is not part of the same initial-hidden action-tab pattern.

The generic visibility documentation is exact:

`Show/hide tab chung: chỉ Info luôn hiện, còn lại ẩn khi không có quyền.`

Therefore the verified lifecycle is:
- frames may exist before authorization is resolved;
- Info remains the invariant visible/fallback page;
- other tabs are shown/hidden according to current permission/plan state.

This is safer than constructing/destroying the entire Notebook structure on every server permission update.

## 6. Info fallback when permissions change

Exact original behavior:

`Nếu tab đang chọn vừa bị ẩn (mất quyền) → chuyển về Info.`

Therefore Info is the lifecycle safety/fallback tab.

## 8. Scroll-wrapper helper

`_make_scrollable` exact doc:

`Wrap frame content in Canvas+Scrollbar. Returns inner_frame for packing widgets.`

Recovered implementation components:
- `Canvas`
- vertical `Scrollbar`
- `create_window`
- `yscrollcommand`
- `scrollregion`
- `<Configure>`
- `<Enter>` / `<Leave>`
- global `<MouseWheel>` bind while pointer is inside;
- unbind on leave;
- scrollbar is packed/forgotten depending on required content height.

The `_new_tab` path contains `wrap_scroll`, so selected tabs can opt into this wrapper without each tab implementing its own shell scrollbar.

Exact per-tab wrap-scroll Boolean for every potential tab is not fully source-expression visible; where Gate-B gives direct scroll geometry, that remains authoritative.

## 9. Central selected-tab refresh lifecycle

Exact docs:

`Khi chuyển tab: dừng refresh tab cũ, chạy refresh tab mới ngay.`

and:

`Sau khi build xong: chỉ tab đang chọn được poll, còn lại dừng hết.`

The shell uses:
- `_on_tab_changed`
- `_selected_tab_key`
- `_sync_tab_refresh`
- `_set_tab_refresh`
- `_sync_initial_refresh`
- `_TAB_REFRESH_KEYS`
- per-tab `_start_refresh` / `_stop_refresh` when present.

Therefore tab loading includes lifecycle ownership of polling, not only widget selection.

## 10. Permission/account-limit state does not normally destroy content

Exact doc:

`Toggle normal/disabled theo has_permission() + check_account_limit() — ko destroy.`

Another exact doc:

`Check hạn mức acc → toggle action tabs khi state đổi (gọi từ heartbeat).`

This separates two operations:
- **visibility**: Notebook tab shown/hidden;
- **enabled state**: child widgets normal/disabled without destruction.

Reconstruction must not rebuild every tab merely because account-limit/permission state toggles controls.

## 12. Reconstruction contract

For parity:

1. create all potential Notebook frame slots in the recovered insertion order;
2. keep Info as invariant fallback;
3. initialize permission-controlled action/dev tabs hidden as required;
4. show/hide using Notebook state when permissions/plan change;
5. if selected tab becomes hidden, select Info;
6. build tab content once when first needed, with controlled rebuild only through the recovered rebuild path;
7. attach scroll wrapper only where configured;
8. coordinate refresh so only the selected refresh-capable tab polls;
9. disable child controls for permission/account-limit conditions without destroying tab content;
10. preserve Gate-B visible 11-tab order for the supplied normal state.
