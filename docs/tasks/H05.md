## 1. Per-account Train target is a saved-coordinate preset name

FarmTab exact documentation for `_preset_to_vars`:

`Tên tọa độ lưu sẵn → (map_var, x_var, y_var). (None,None,None) nếu không thấy.`

The per-account row owns:
- `farm_var`
- the nested `_go_move` callback
- `_preset_to_vars`
- then `_move_acc`.

So the per-account Train combobox selects a **named saved-coordinate preset**, and that name resolves to the live preset row's:
- map variable
- X variable
- Y variable.

The movement layer does not persist a separate immutable copy of the target coordinates.

If a preset no longer exists, `_preset_to_vars` returns the explicit None triple. H05 does not invent coordinates for a missing preset.

H01 already locked:

The row button `Tới bãi train` resolves its `farm_var` preset to `mv/xv/yv` and calls `_move_acc`.

The all-account action `_move_all` iterates checked rows, resolves each row's selected preset, and launches their movement work in parallel.

This preserves a single per-account movement contract for:
- row/manual move;

## 5. Target coordinates are tile coordinates; movement primitive uses 32 pixels per tile

The active Truyền move-retry block contains exact integer **32** beside the movement/wait-for-arrival surface.

The near-target helper separately contains exact float **32.0** beside live `PosX/PosY` conversion.

The generic movement contract documented by `fast_travel` states `move_character` receives pixel coordinates and describes target conversion as:

`pixel = tile*32`.

Thus the Train coordinate contract is:

- saved X/Y = tile coordinates;
- primitive path coordinates = tile × **32 pixels**.

Do not reinterpret saved Train X/Y as raw screen coordinates or raw world pixels.

## 8. Forward Truyền route selection is embedded in FarmTab movement

The selected target map is resolved from the preset, then checked against `TRUYEN_DAI_LY_ROUTES`.

For an ordinary target with no Truyền shortcut, FarmTab retains the normal `move_character` path.
