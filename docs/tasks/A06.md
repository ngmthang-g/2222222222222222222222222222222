## 2. `bootstrap.exe` — VERIFIED behavior

Recovered logic:

1. `SetWorkingDir %A_ScriptDir%`.
2. Reads argument count through `A_Args.MaxIndex()`.
3. If fewer than **2 arguments**, exits immediately.
4. `NewFile := A_Args[1]`.
5. `TargetFile := A_Args[2]`.
6. Enters an **unbounded loop**.
7. If `NewFile` does not exist: sleep **500 ms** and retry.
8. If it exists: `FileMove, %NewFile%, %TargetFile%, 1` (overwrite enabled).
9. If move succeeds (`!ErrorLevel`), break and exit.
10. If move fails: sleep **500 ms** and retry.

There is **no timeout** and no maximum retry count in the recovered bootstrap script.

### Role in updater self-replacement

`update.exe` launches bootstrap with exactly:

`"bootstrap.exe" "update\\update.exe" "update.exe"`

where all paths are constructed under `A_ScriptDir`.

Because the currently running `update.exe` may remain locked while it is still alive, bootstrap repeatedly tries to move the newly downloaded updater over the current updater until the move succeeds. The updater then exits after relaunching TLM, allowing the replacement loop to complete.

This self-replacement relationship is **VERIFIED from the recovered scripts**.

## 3. `update.exe` — source selection

Updater internal version string: **`1.2`**.

It logs to:

`A_ScriptDir\\update_replace.log`

The first command-line argument is treated as an optional download link.

Supported parsing:

- If argument contains `pixeldrain.com`: extract `/u/<id>` and use source host `pixeldrain`.
- Else if argument contains `drive.google.com`: extract a Google Drive file ID.
- If parsing fails, argument is missing, or host is unrecognized: use the compiled default Google Drive file ID:
  `12BguvI-s4tLE6_rRfB9208TSJuKZMzRT`

Password selection:

- Pixeldrain: empty ZIP password.
- Google Drive/default Drive source: ZIP password **`1`**.

## 4. Download flow — VERIFIED

Working files under `A_ScriptDir\\update`:

- `update.zip`
- `dl.ps1`
- `progress.txt`
- later `unzip.log`, `unzip.cmd`, `move.ps1`

The updater creates a small always-on-top GUI titled **`Đang cập nhật...`** with progress and detail labels.

It generates and launches hidden PowerShell with:

`powershell -NoProfile -ExecutionPolicy Bypass -File "<update>\\dl.ps1"`

PowerShell facts:

- Forces TLS 1.2.
- Pixeldrain URL: `https://pixeldrain.com/api/file/<id>?download`.
- Google Drive URL: `https://drive.usercontent.google.com/download?id=<id>&export=download&confirm=t&authuser=0`.
- User-Agent: `Mozilla/5.0`.
- Streams response into `update.zip` using a **65,536-byte buffer**.
- Writes progress to `progress.txt` as `pct|message`.

AHK polls progress every **300 ms**.

After download:

- `dl.ps1` and `progress.txt` are deleted.
- Missing ZIP => error UI/message and return.
- ZIP size below **10,000 bytes** => treated as failure and return.

### Integrity/authenticity behavior

The recovered updater script contains **no cryptographic hash verification, no digital-signature verification, and no certificate pinning for the downloaded update ZIP**.

Its explicit pre-extraction acceptance checks are file existence and file size >= 10,000 bytes. Extraction success is checked later via 7-Zip output/exit code.

A06 records this as original behavior only; it does not modify it.

## 5. Extraction flow — VERIFIED

7-Zip selection:

1. Prefer bundled `A_ScriptDir\\tools\\7z.exe`.
2. If missing, fallback to `C:\\Program Files\\7-Zip\\7z.exe`.
3. If still missing, log error, show message, and return.

Updater generates `update\\unzip.cmd`.

- With Drive password: `7z x update.zip -p1 -o<update-dir> -y`.
- With Pixeldrain: same extraction without `-p`.
- stdout/stderr go to `update\\unzip.log`.
- CMD appends `EXITCODE=<ERRORLEVEL>` to the log.

AHK displays synthetic/fake extraction progress while the process runs.

Extraction is considered successful only if `unzip.log` contains both:

- `EXITCODE=0`
- `Everything is Ok`

Otherwise it shows an extraction failure and returns.

## 6. Replacement/copy flow — VERIFIED

Updater then generates hidden `move.ps1`.

Important path fact:

`ExtractDir := A_ScriptDir`

Since packaged `update.exe` lives in `TLMTool.dist`, **the destination is the currently installed `TLMTool.dist` directory**, not the outer package root.

PowerShell searches under `update\\` for the **first directory whose name matches `TLMTool*`**. It then expects:

`<matched-folder>\\TLMTool.dist`

If found:

1. `robocopy <new TLMTool.dist> <current A_ScriptDir> /E /XF update.exe ...`
2. Therefore all files/subdirectories from the new `TLMTool.dist` are copied over the current `TLMTool.dist`, **excluding `update.exe`**.
3. The new package's `update.exe` is copied separately into `A_ScriptDir\\update\\update.exe`.
4. The extracted top-level `TLMTool*` folder is deleted with `rd /s /q`.

If expected folder structure is missing, `update\\error.log` is written. AHK checks this file and aborts with an error message if it exists.

### Outer launcher update behavior

Because `move.ps1` only copies the extracted **`TLMTool.dist` contents** into the current **`TLMTool.dist`**, the recovered A06 logic does **not** copy/update the outer root `TLMTool.exe` launcher.

## 7. Updater self-replacement — VERIFIED

After copy:

- `move.ps1` and `update.zip` are deleted.
- `NewUpdaterInUpdate := A_ScriptDir . "\\update\\update.exe"`.
- If that file exists, updater defines:
  - `BootstrapExe := A_ScriptDir . "\\bootstrap.exe"`
  - `ThisExe := A_ScriptDir . "\\update.exe"`
- If bootstrap exists, it launches hidden:

`Run, "%BootstrapExe%" "%NewUpdaterInUpdate%" "%ThisExe%",, Hide`

Bootstrap then performs the retrying overwrite described above.

If bootstrap is missing, the updater only logs the error; it does not abort the remainder of the script.

If no new updater exists, it logs that bootstrap is skipped.

## 8. Relaunch after update — VERIFIED

At the end:

1. GUI shows completion.
2. Sleeps **1,000 ms**.
3. Destroys update GUI.
4. Executes:

`Run, %A_ScriptDir%\\TLMTool.exe`

5. `ExitApp`.

Because updater's packaged location is `TLMTool.dist/update.exe`, this command relaunches the **inner** `TLMTool.dist/TLMTool.exe` directly, not the outer root launcher from A05.

## 9. Static behavioral edge cases recorded, not fixed

These are direct consequences of the recovered script and are preserved as evidence rather than changed:

- Bootstrap has no timeout; it can retry forever if replacement cannot succeed.
- `update\\error.log` is checked after `move.ps1`, but the beginning of the updater does not explicitly delete a pre-existing `error.log`; a stale file can therefore remain relevant to a later run.
- Downloaded ZIP authenticity is not cryptographically verified by this AHK script.
- The updater copies only `TLMTool.dist`, not the outer root launcher.
- The extracted package selector uses the **first** directory matching `TLMTool*`.

These are not "fixes" or judgments; they are static parity facts for later reconstruction.
