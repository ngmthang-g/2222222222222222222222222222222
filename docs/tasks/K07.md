## 5. respawn_event is recoverable, not terminal

At the beginning of `_punish_exec_sequence` the frozen branch says:

`respawn_event đang set → clear, cho heal/move rời map 87`.

Therefore the design is:

1. monitor notices death/Map87;
2. revive click and/or `respawn_event.set()`;
3. current combat/action can unwind through the already-frozen stop/recovery surface;
4. the next Trừng Ác cycle consumes and clears `respawn_event`;
5. low-HP heal/movement then proceeds to leave Map87.

K06 already proved death during combat can stop the fight early.

A death/Map87 event is therefore not by itself a terminal current-account Trừng Ác stop.
