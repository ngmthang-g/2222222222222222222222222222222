## 1. Tới chỗ train starts from the selected saved preset

The row callback surface directly contains:
- _preset_to_vars
- farm_var
- _ensure_in_lsv
- farm_map
- _move_acc.

The selected account row uses farm_var as the saved-coordinate preset name. I01 already locked:

_preset_to_vars(name) -> (map_var, x_var, y_var)

and returns (None,None,None) when the preset is missing.

The row callback has an exact failure text:

chưa chọn tọa độ Farm hợp lệ

before the _ensure_in_lsv/_move_acc call surface.

Therefore a manual row Tới chỗ train does not use a hard-coded coordinate. It resolves the currently selected saved preset first.

## 8. Exact movement call options

The exact keyword tuple in _move_acc is:

(wait_for_arrival, stop_check)

Thus final movement calls shared move_character with:
- wait_for_arrival=True
- stop_check=<caller supplied callback>.

The manual button path uses the documented None/no-stop semantics; an automatic Farm cycle passes a cancellation callback.

No I03-specific timeout keyword/value is supplied here.

The actual arrival timeout therefore belongs to shared move_character, not to TrainLsvTab.

## 9. No LSV-specific H05-style 8-tile near-target skip

This was checked explicitly because H05 ordinary Train has an 8-tile near-target optimization.

Across the decoded TrainLsvTab module:
- no _is_near helper exists;
- no PosX / PosY constant exists;
- no near/distance/gần-target documentation exists;
- _move_acc locals contain no current-position sample, dx/dy or distance state.

Its own documentation says di thẳng and its only final movement primitive is move_character.

Therefore Train LSV does not implement H05's explicit 8-tile skip inside TrainLsvTab._move_acc.

This does not forbid the shared move_character helper from naturally recognizing that an exact target has already been reached; it only means the separate FarmTab 8-tile pre-skip must not be copied into Train LSV reconstruction.
