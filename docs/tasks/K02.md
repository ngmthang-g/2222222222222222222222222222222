## 1. Account source and refresh lifecycle

DailyTab receives `info_tab` in its constructor and the shared roster refresh uses the `get_windows` surface from that integration.

Exact refresh helpers:
- `_refresh_acc_lists`
- `_start_refresh`
- `_stop_refresh`
- `_schedule_refresh`.

Exact documentation:
- `_refresh_acc_lists`: **Incremental refresh danh sách acc unified.**
- `_start_refresh`: called when the tab is selected.
- `_stop_refresh`: called when switching away.
- `_schedule_refresh`: **Tự động refresh danh sách acc mỗi 5 giây.**

Constructor state includes:
- `_refresh_id`
- `_refreshing`
- `_closing`.

The refresh worker gathers account/window information off the Tk path, then uses `after` to apply row changes on the UI thread.

## 2. HWND identity is bound to PID to defeat handle reuse

Shared identity helpers:
- `_pid_of`
- `_owns_hwnd`
- `_is_window_alive`.

Exact `_is_window_alive` documentation:

> True nếu hwnd còn mở VÀ đúng process đã bind (chống HWND tái sử dụng).

If an HWND now points to a different process, the exact log says:

`[Daily] hwnd=<...> đổi process (pid old → new) — cửa sổ cũ đã mất, tạo lại row mới`.

The row identity flow directly references:
- `bind_window_identity`
- `unbind_window_identity`.

Thus an integer HWND alone is not sufficient identity for a Daily row.

## 3. Row refresh is create-or-update, not full rebuild

Exact `_add_or_update_row` documentation:

> Add row mới nếu chưa có, update tên/level/map nếu đã có.

A row tracks current character display data and the bound process identity. Existing valid rows are updated in place.

Exact `_remove_stale_accs` documentation:

> Xóa acc của window đã đóng HOẶC đã đổi process (HWND tái sử dụng).

Therefore refresh semantics are:
1. discover current windows;
2. add/update current rows;
3. remove closed or PID-reused rows;
4. update scroll geometry.

## 4. Scroll-region update is deliberately debounced

The frozen Daily code contains a detailed bug-fix contract:
- old logic cached row count too early;
- later geometry growth could leave the scrollregion stale;
- current logic debounces by time instead.

Exact debounce interval: **30 ms**.

`_request_scroll_update` always schedules recalculation after geometry settles; `_update_scroll_region` recalculates the canvas scrollregion on the Tk thread.

This is shared account-list behavior and must not be “optimized” back to row-count-only invalidation.

## 8. All state-widget mutation is marshaled to Tk main thread

Exact shared methods:
- `_set_state`
- `_schedule_state_label`
- `_apply_state_label`.

Exact frozen documentation says:
- state update is safe from worker threads by routing through `after`;
- `_schedule_state_label` marshals `_apply_state_label` through `after(0)`;
- touching Tk widgets cross-thread can terminate the process silently.

Therefore reconstruction must not update Daily row widgets directly from background workers.

## 9. Per-row session protection uses Event + generation

Daily contains module-level helper `_GenStop`.

Exact frozen documentation explains why it exists:

> Fix race Dừng→Bắt đầu nhanh: worker cũ sống sót qua _stop_event.clear() ... rồi lái acc song song với worker mới.

`_GenStop` wraps the row's real `_stop_event` plus a captured generation:
- `is_set()` becomes true when the real event is set **or when row `_gen` no longer matches the worker generation**;
- `set()` and `clear()` pass through to the real Event.

This is a direct stale-worker protection mechanism.

Do not reconstruct Daily with only one reusable Event and no generation check.

## 12. Bottom Bắt đầu/Dừng lại is an all-row coordinator

Exact `_start_all_accs` documentation:

> Nút 'Bắt đầu/Dừng lại': toggle.
> - Đang chạy → dừng tất cả acc (set _farming_acc=False + _stop_event).
> - Đang dừng → start activity cho mọi acc chưa chạy (per-acc thread).

### Stop branch
Exact constants show:
- log `[Bắt đầu] Gửi lệnh dừng tất cả acc...`;
- row play display restored to `▶`;
- bottom text restored to `Bắt đầu`;
- green `#388e3c`;
- `_sync_start_tab_btns`;
- log `[Bắt đầu] Đã dừng tất cả acc`.

The actual worker threads are cooperative and may still be winding down after the stop signal.

### Start branch
The coordinator:
- performs shared injection/window preparation;
- selects rows not already running;
- chooses the current activity per row;
- starts a per-account thread;
- logs `[Bắt đầu] Không acc nào cần chạy` when nothing qualifies;
- otherwise logs `[Bắt đầu] Đã chạy <N>...`;
- switches the bottom action to `Dừng lại` with red `#f44336`;
- ensures the singleton all-account monitor exists.

A Trừng Ác row requiring teleport but lacking a hotkey is explicitly skipped with:

`[Bắt đầu] Thiếu phím tắt phù — bỏ qua trừng ác`.

That is a coordinator selection rule; route semantics remain K03+.
