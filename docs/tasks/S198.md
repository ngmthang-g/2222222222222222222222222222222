## Source evidence

- Independent public `libil2cpp` object-header definition: `Il2CppString` contains `Il2CppObject object` (two Win64 pointers), `int32_t length`, then `Il2CppChar chars[]`. Consequently the **standard** x64 IL2CPP object ABI uses string length +0x10 (4B) and UTF-16 data +0x14 (2B/char). See upstream-like source [libil2cpp object internals](https://github.com/Kasuromi/libil2cpp/blob/main/il2cpp-object-internals.h), and independent [il2cpp_ref](https://github.com/dreamanlan/il2cpp_ref/blob/master/libil2cpp/il2cpp-object-internals.h).
- **Important precision:** the generic IL2CPP ABI + original `_rstr` UTF-16 literal do NOT themselves prove that the frozen TLM `Reader._rstr` uses exactly these offsets and bounds or that an *active game* is compatible. This S198 decoding is consequently an independently reconstructed **read-only candidate**, not a static-proven recreation of that function's control flow.
