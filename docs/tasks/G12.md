## 3. Party runtime identity contract

Use G02 + G03.

Physical identity:
- shared `start_tab.get_windows()` source
- Party does not EnumWindows independently
- recurring Party refresh = **3000 ms**
- background window/character read
- main-thread Tk apply
- runtime generation identity = **HWND + PID**.

Same numeric HWND with a new PID:
- old identity is unbound;
- old member/widget is removed;
- new process generation is created fresh.

Display/config identity:
- sanitized `RoleName`
- temporary `Window ...` fallback when name unavailable.

Action identity:
- RoleID resolved live via `read_own_ids + hwnd_of_pid`
- TeamID read live via `read_team_id`
- TeamID 0 / 0xFFFFFFFF = no team
- TeamID None = read failure, never successful no-team.

Do not persist or conflate these identity layers.

## 7. Team protocol contract

Use G10.

One cluster:

### B0 — auto-accept
- write `UTILITIES.AutoAcceptInviteTeam=True`
- read back
- False/None means warning/unconfirmed, not fabricated success.

### B1 — leave existing team
- skip 0 / 0xFFFFFFFF
- leave packet channel **200057**
- action **4**
- payload `4:<ownRid>`
- then wait outside-team state
- timeout logs and continues.

### B2 — create team
Packet first:
- channel **200057**
- action **0**
- payload `"0"`
- verify real leader TeamID.

Click fallback only if needed:
- leader 1366×768
- conditional (391,683)
- conditional (34,462)
- tail (27,467) → (154,214) → (127,336)
- **1 second between clicks**
- cancellation-aware.

### B3 — burst invite
- packet channel **200051**
- team prefix `5:`
- payload `5:<targetRoleID>`
- burst all members
- shared TeamID wait
- exactly one resend round for missing members
- final wait
- remaining missing members produce diagnostic/manual-autoaccept warning rather than an infinite retry loop.

## 8. Post-party dispatch contract

Use G11.

Global aggregate only:
- wait → no-op
- phoban → whole-tab Phó Bản activation
- train → per-account Train
- train_lsv → per-account Train LSV
- don → per-account Dồn vàng.

Generic Train-like routing:
1. preserve just-partied target set as name + Party-HWND;
2. select destination tab first;
3. background readiness wait:
   - `want.issubset(have)`
   - **1.0s** cadence
   - max **20s**;
4. main-thread dispatch;
5. exact HWND match first;
6. name/lowercase fallback;
7. fresh-resolution fallback;
8. use destination row's **current HWND**;
9. skip missing account individually;
10. skip already-running `_farming_acc`;
11. call destination `_toggle_single_farm`.

Single-cluster `▶ Tạo nhóm N` does not independently trigger post-party routing.

## 9. UNKNOWN classification

All remaining G01–G11 unknowns are preserved in the Party parity matrix and fall into exactly three classes.

### IMPLEMENTATION_SAFE
These are source-syntax or micro-order details where the externally visible contract is already bounded strongly enough for later reconstruction:
- exact Tk-after worker→UI handoff delay;
- exact destroy/cleanup statement ordering where lifecycle cancellation is already required;
- exact `_saving_enabled` flip statement timing during load;
- exact current-vs-legacy config branch syntax;
- exact malformed-JSON exception syntax;
- exact legacy-key delete/pop syntax;
- exact fresh-map dictionary construction syntax;
- exact UI reset callback micro-order where final states are locked.

These must not be falsely labeled “original exact source,” but they do not block implementing the verified behavior.

### RUNTIME_ONLY
These change observable behavior and must be compared against the original Windows runtime:
- first Party refresh tick: immediate vs first delayed tick;
- same-cluster collision between global `Bắt đầu` and that cluster's `▶ Tạo nhóm`;
- explicit global/manual cancel: whether post-party routing is suppressed or still runs;
- exact user-visible behavior when only one selected account remains online;
- exact handling of malformed/current-vs-legacy config edge cases if parity requires byte-for-byte semantics.

Do not lock these branches before original-vs-reconstruction runtime evidence.

### STRONGER_DECOMPILATION_REQUIRED
These are internal constants/critical sections not safely recoverable from the readable Nuitka constant stream and must not be guessed:
- exact numeric invalid-RoleID sentinel, if one exists;
- exact `_run_lock` critical section;
- exact `_last_targets` reset/merge statement sequence;
- exact numeric `CREATE_RETRY`;
- exact numeric bindings for symbolic Party timing constants including `AUTOSET_DELAY`, `LEAVE_DELAY`, `WAIT_LEFT_TIMEOUT`, `TEAMID_POLL`, `CREATE_PACKET_TIMEOUT`, `WAIT_TEAM_TIMEOUT`, `INVITE_DELAY`, `GROUP_JOIN_POLL`, `GROUP_JOIN_TIMEOUT` and exact `BURST_INVITE_DELAY`.

Runtime measurement may later constrain some of these, but static reconstruction must not assign the pooled floats arbitrarily.
