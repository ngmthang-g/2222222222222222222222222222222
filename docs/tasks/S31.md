## 2. Implemented code (pure offline, no ADB calls)
- NEW `src/adb_identity_evidence.py`:
  - `inspect_captured_adb_devices(captured_text, captured_at, hints_by_serial)`: parser for an **already acquired** conventional `List of devices attached` output. Does NOT run adb, spawn its daemon, install APK, attach Frida, query Android nor fetch IP/aid. Input may be constructed in tests and is not independently authenticated. Strict no-capture/error distinction; row states online (`device`), `offline`, `unauthorized` and other transport statuses. Reject malformed header/rows, excessive input, incompatible hint records and hints not matching captured serials.
  - `GuestIdentityHint`: supplied observed aid/hwid/guest IPv4/guest game PID, never self-read; validates field types and PID but does NOT assert signed provenance.
  - `AdbIdentityEvidence`: preserves original rows and identifies duplicate **serials, Android IDs, HWIDs, guest IPs**. `unique_serial_for(field,value,now)` returns a serial only if capture fresh, transport state `device`, and mapping unique. Collision never arbitrarily selects an emulator; an untrusted IP hint is only diagnostic, not permission/control authority.
  - `freshness(now)`: diagnostic 30-second S31 LOCAL default; P02 has a 5-minute cached aid duration but that is **not** a general ADB device identity guarantee and is not reused for authorization.
  - `identify_possible_serial_rebinds(previous,current,now)`: flags same unique aid on a different serial as **POSSIBLE_ONLY_NOT_VERIFIED**, not automatic rebind; suppresses on clone collisions, stale or ambiguous captures.
  - **`emulator_account_count=None`, `combined_running_count=None`, `is_authoritative_account_total=False`** regardless of how many connected transports or hints are supplied. Guest PID cannot become Windows PID count; S26 launch preflight still rejects unknown combined total. The module is independent of S29/S30 output and cannot bypass permission_guard.
