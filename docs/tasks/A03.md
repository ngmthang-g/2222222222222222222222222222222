## METHOD
A03 is static-only. No executable was launched.

Primary classification order:
1. `.exe` → EXE
2. `.dll` → DLL
3. `.pyd` → PYD
4. application data paths (`TLMTool.dist/data/*`, `version.dat`, `proxy_working.txt`) → DATA
5. remaining package support/runtime files → RESOURCE

PE validation was not based on `MZ` alone. A file was counted as a robust PE only when:
- DOS `MZ` header exists;
- `e_lfanew` is in-range;
- `PE\0\0` signature exists;
- machine type is recognized;
- section count is reasonable;
- PE optional-header magic is valid;
- section table/raw file ranges are structurally plausible.

## IMPORTANT DATA FINDINGS
The DATA category contains **23 files** and is not homogeneous.

- **6** `resources*.dat*` files are structurally valid **x64 PE DLL-format** files whose sections are `UPX0`, `UPX1`, `UPX2`. This is evidence of a UPX-style packed PE layout; A03 does not claim their runtime role.
- `version.dat` is a structurally valid **x64 PE DLL-format** file with normal-looking sections: `.text`, `.data`, `.rdata`, `.pdata`, `.xdata`, `.bss`, `.edata`, `.idata`, `.reloc`.
- **14** other `.dat` files begin with `MZ` and contain a `PE\0\0` marker at the referenced location, but fail robust PE structural validation. They remain DATA, not DLL/EXE.
- **2** DATA files are plain text: `data/automove_log.txt` and `proxy_working.txt`.

An `MZ` prefix alone is therefore not treated as evidence that a file is executable.
