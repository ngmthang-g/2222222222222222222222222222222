## Main findings
- UI interval is Lặp (s), backed by sec_var with digits-only/blank-edit validation.
- Current default and malformed-load fallback are 30 seconds.
- Exact load interval constant cluster binds min + 0 + 60 + sec + TypeError/ValueError + fallback 30; current normalized storage/UI domain is 0..60 seconds.
- Blank/zero is not a usable repeating interval; normal runnable interval domain is positive 1..60 seconds.
- _slot_loop exact doc fixes first-send order: send immediately, then wait configured interval, then repeat.
- Interval wait is through _stop_event.wait(max(...)), so stop can interrupt the wait.
- Up to four slots per account run independent loops/timers.
- The Rao definition is re-resolved on every loop. Editing interval while running does not reschedule the wait already underway, but the next cycle uses the edited value without restart.
- No separate fast retry/backoff timer is recovered after normal send/no-echo failure; normal attempts converge to the configured wait unless a hard invalid/stop condition ends the slot.
- If a referenced Rao becomes deleted/invalid between cycles, the affected slot fails closed/stops instead of continuing on stale cached values.
- Live Windows scheduler jitter/server echo timing remains runtime-required.
