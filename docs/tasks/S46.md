## Confirmed race and fix
- **S45 integration defect:** `F09ReadOnlyTabLifetime.close()` invoked `worker.shutdown(timeout=0)` from Tk; S43 `worker.shutdown()` calls `stop(timeout)`, which synchronously acquires `_lifecycle_lock` **before** a zero-second `join`. If another thread already holds that lock during a stop/join, the Tk `<Destroy>` callback waits for that thread despite `timeout=0`. A real GUI deadlock/long freeze is possible.
- **`src/login_schedule_worker.py` S46 change:** new explicit `request_shutdown()` sets the one-way `_closed` latch and `Event.set()` immediately, **without any lock or join**. Existing `shutdown(timeout)` now calls `request_shutdown()` then `stop(timeout)`, preserving S42/S43 public semantics for non-Tk callers. `start()` checks closure again after clock callback and after `_cancel.clear()` and thread start; reentrant shutdown wins, no rearmed worker.
- **`src/login_schedule_lifetime.py` S46 change:** `close()` now uses `worker.request_shutdown()` from Tk, evaluates thread_alive without waiting, records `CLOSED` or `CLOSING_WORKER`; `finish_close(timeout)` alone joins asynchronously after GUI teardown. A failure in Tk `preview.shutdown()` is recorded as `BLOCKED_PREVIEW_TEARDOWN` but still **always** signals worker cancellation in `finally`. Never claims full success if Tk teardown raised.
- Not claimed as original instruction-level micro-order: S46 is a narrowly verified GUI responsiveness/cancellation safety correction.
