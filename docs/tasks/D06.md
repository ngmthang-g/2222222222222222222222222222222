# D06 — Configuration and data files

## STATUS
**VERIFIED_WITH_OPAQUE_DATA_ROLES_EXPLICITLY_UNKNOWN**

D06 separates packaged data/resources from runtime-generated configuration/state files. It reuses Gate-A PE classification and rechecks file hashes, magic, and filename references against the frozen archive.

## 1. Packaged DATA set

Gate A identified **23** package DATA files:
- 21 files under `TLMTool.dist/data/`
- `TLMTool.dist/proxy_working.txt`
- `TLMTool.dist/version.dat`.

D06 additionally treats `TLMTool.dist/ppx/Default.ppx` as a configuration resource.

## 2. Opaque MZ/PE-like .dat files

Fourteen packaged `.dat` files are high-entropy opaque files:
`accounts.dat`, `app_state.dat`, `auth_token.dat`, `cache.dat`, `config.dat`, `license.dat`, `logs.dat`, `manifest.dat`, `package.dat`, `sec_key.dat`, `session.dat`, `settings.dat`, `signature.dat`, `user_profile.dat`.

Properties:
- all begin with `MZ`;
- entropy is roughly **7.996–7.999 bits/byte**;
- Gate A found PE-like markers but they fail robust PE structural validation;
- the exact filenames are not present as runtime name references in the inner EXE.

D06 therefore does **not** assign semantic roles based on suggestive filenames. They remain `OPAQUE_MZ_PE_LIKE_INVALID / runtime role UNKNOWN`. A filename such as `license.dat` is not evidence that it stores the active license.

## 3. resources.dat family

Six files are structurally valid x64 PE DLL-format containers with UPX0/UPX1/UPX2 sections:
- active `resources.dat`
- five backup/old copies.

Only active `resources.dat` is directly referenced by name in the inner EXE.

Strong evidence:
- `dll_injector` path helper explicitly returns `./data/resources.dat`;
- multiple feature blocks contain exact text `Inject DLL (resources.dat)`;
- active `resources.dat` exports hook/trampoline functions and custom game/input symbols including MinHook `MH_*`, `Get_WM_MY_SYNC_CLICK`, `Get_WM_MY_SYNC_KEY`, `Get_WM_MY_SYNC_WHEEL`, `DetourGRoleOnTick`, and cursor/window/socket/registry detour functions.

Conclusion: **active resources.dat is the injected game payload DLL disguised by a .dat name.**

Backup names are package history artifacts unless later evidence proves runtime selection.

Integrity fact:
- `resources.dat.bak-20260923`
- `resources.dat.old-locked`

are byte-identical with SHA-256 `e301c0851aa28e79e561c85d02342c2ff3332daf15e521bc84f01544aa942efd`.

## 4. version.dat

`version.dat` is a structurally valid x64 PE DLL-format file, referenced by Start logic together with `version.dll`.

Exports:
- `GetFileVersionInfoA/W`
- `GetFileVersionInfoSizeA/W`
- `VerQueryValueA/W`.

It is classified as a **version.dll-compatible proxy PE**, not ordinary configuration data.

## 7. Runtime INI/config files

### %APPDATA%/TLMTool/settings.ini
Recovered behavior:
- shared `read_settings` / `write_settings`;
- `RawConfigParser` safe read;
- duplicate keys: last wins;
- writes use a temp file + `os.replace` for atomic replacement;
- Start stores `grid_cols`, `grid_rows`, `detached_auto_open`, `detached_grid`;
- other feature tabs reuse the same settings contract.

This is the main persistent feature/settings INI.

### config.ini
Two distinct path contexts are visible and must not be conflated:

1. `TLMInfoTab._get_config_path`
   - exact text: `Return config.ini path alongside this script.`
   - used for Info/license/server state.

2. shared central config helper
   - exact docs reference `%APPDATA%\TLMTool\config.ini`
   - `CONFIG_PATH` / `CONFIG_DIR`
   - load/save section/key values.

D06 preserves both path contracts instead of assuming they are the same physical file in every compiled context.

## 8. Login/runtime state files

Recovered:
- `login_online.json` — online/login tracking with JSON dump evidence
- `last_login_times.json` — login scheduling/history timestamps.

These are runtime-generated state, not immutable package resources.

## 9. Forwarder/proxy runtime files

Strong exact-name evidence includes:
`forwarder_mode.txt`, `forwarder_idx.txt`, `forwarder_stats.json`, `forwarder_pid.txt`, `forwarder_advance.txt`, `forwarder_targets.txt`, `forwarder_pinned_proxy.txt`, `forwarder_force_direct.txt`, `proxy_alloc.txt`, `proxy_alloc.lock`, `proxy_bad.txt`, numbered/multi-instance variants, and `proxy_last_refresh.txt`.

These files coordinate mode, PID, proxy allocation, pinning, rotation and cross-process state.

## 10. Emulator guest configuration

Exact path pattern: `/sdcard/TLM/tlm_*.json`.

`emu_input` documentation says it reads overlay/config JSON from the Android guest through ADB. This is separate from PC-side `settings.ini`.

## 11. Log files

Additional runtime logs:
- `tlm_memory.log` — memory diagnostics
- `log/tlmtool.log` — central tool session log
- `automove_log.txt` — injected automove/tick/perf log.

Logs are not configuration sources.

## 12. JavaScript helper boundary

Package also contains:
- `emu_client.js`
- `ld_remote.js`.

They are referenced by emulator code but are deferred to **D07** for content/behavior analysis.

## 13. Reconstruction implications

Reconstruction must keep these categories separate:

- immutable packaged payload/template: resources.dat / version.dat / Default.ppx
- persistent PC config/state: settings.ini / config.ini / login*.json / forwarder*.txt
- Android guest config: /sdcard/TLM/tlm_*.json
- logs: tlmtool.log / tlm_memory.log / automove_log.txt
- opaque package artifacts: 14 high-entropy MZ/PE-like .dat files.

Do not replace the opaque 14 files with invented JSON/INI schemas merely because their filenames look descriptive.
