## Main findings
- Current Dồn dedicated-tab all-account toolbar has exactly three quick movement actions under “Điều khiển tất cả”: Tới nơi nhận, Tới chỗ bán, Tới nơi train. The big bottom Bắt đầu button is separate and is wired to _toggle_farm.
- Current quick-button command mapping is frozen from the exact UI constant block:
  - Tới nơi nhận -> _move_all_recv
  - Tới chỗ bán -> _move_sell_acc
  - Tới nơi train -> _move_all
- These dedicated-tab quick movement actions are dispatched off the Tk main thread through daemon Thread surfaces.
- _checked_rows is not a checkbox-selection helper in the current build despite legacy wording. Its exact doc says bulk actions use all accounts in the list and exclude receiver accounts because receivers run their own flow.
- _move_all therefore targets the nonreceiver/donor universe and moves those accounts to their configured Train coordinate. Its exact doc says the move is parallel.
- _move_sell_acc targets receiver accounts only and moves each receiver to that account's selected sell coordinate. It is movement-only; it is not the _sell_all inventory-selling helper.
- _move_all_recv is role-aware across the full account list:
  - donor accounts -> move toward the receiver chosen by the current manual receiver-selection policy (ready lowest-gold/hour when available; L06 manual fallback to first valid receiver when none is ready);
  - receiver accounts -> move to the receive-coordinate variable attached to their receiver row. In the current L05 architecture every row aliases the one shared _recv_coord_var, so “row-specific” compatibility wording resolves to the shared current Dồn point.
- _stop_all, _farm_all and _sell_all remain real DonVangTab class methods with exact docs “... các acc được tick — song song”, but no current Dồn toolbar or StartTab button binding to these methods was recovered.
- Those three helper docs use stale “được tick” wording; their current row universe comes from _checked_rows = all nonreceiver accounts.
- _stop_all is the parallel wrapper around per-account stop behavior.
- _farm_all is a parallel wrapper around _farm_acc, and _farm_acc is only the internal StartAutoFight Train primitive. It is **not** equivalent to the current big Bắt đầu/_toggle_farm full lifecycle.
- _sell_all is the parallel actual sell-flow helper. It is **not** the visible Tới chỗ bán movement button.
- Current big Bắt đầu/_toggle_farm remains the authoritative all-account lifecycle control: start only not-yet-farming rows, stop only currently-farming rows, and classify receiver vs donor at session start as frozen by L07.
- StartTab Dồn quick controls preserve the same backend semantics:
  - Dồn vàng -> _toggle_donvang_cmd -> DonVangTab _toggle_farm, with text synchronized between StartTab and Dồn tab;
  - Tới nơi nhận -> _donvang_action calling _move_all_recv;
  - Tới chỗ bán -> _donvang_action calling _move_sell_acc;
  - Tới nơi train -> _donvang_action calling _move_all;
  - Cấu hình -> _goto_donvang_tab.
- _donvang_action runs the delegated Dồn bulk action in a worker thread; the Cấu hình button is the separate tab-navigation path.
- No dedicated all-action cancel token/queue surface was recovered for the three standalone quick movement commands. They are not the same worker ownership as _toggle_farm. Exact overlap/cancellation if a user starts/stops Farm while one standalone quick movement command is already running remains runtime-required and is not guessed.
- Packaged runtime log contains no correlated current Dồn bulk-action trace, so ordering/timing parity remains environment-required.
