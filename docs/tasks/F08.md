## 1. Shared proxy parser contract
The forwarder parser returns `(host, port, user, password, protocol)` where protocol is `socks5`, `socks4`, `http`, or None/auto.

Explicit supported forms:
- socks5://host:port
- socks4://host:port
- http://host:port
- host:port@user:pass
- user:pass@host:port
- host:port:user:pass
- host:port.

Login's private-proxy editor calls the shared proxy parser family. The UI hint advertises only a subset; the backend parser surface is broader.

## 2. Free proxy pool lifecycle
`proxy_refresh` owns:
- proxy_working.txt
- proxy_last_refresh.txt
- four bundled download sources;
- parallel liveness checks;
- deduplication;
- speed sorting;
- thread-safe periodic snapshots while checks are still running.

Exact documentation says it downloads proxies, checks them, and saves live proxies into proxy_working.txt.

Alive proxies are explicitly sorted fastest-first before final save.

The module has a single-refresh lock. A concurrent refresh is skipped rather than starting a second overlapping refresh.

Lower-level refresh also has an exact `proxy vừa tải < 60s trước` skip guard unless the call is forced.

MAX_CHECK is statically encoded as 300 in the proxy_refresh constant block. Exact MAX_WORKERS and every socket timeout constant are not all mapped with enough certainty here, so they remain outside the F08 parity contract.

## 3. Login freshness threshold is 5 minutes
`LoginTab._ensure_proxies_fresh` has exact documentation:
`Tải lại proxy từ internet nếu proxy_working.txt quá cũ (>5 phút).`

It runs blocking inside a worker thread so the new list is fully written before an index is advanced/picked.

If the list is still fresh, Login logs that refresh is skipped.

Thus Login's list freshness threshold is 5 minutes.

## 4. A real refresh resets forwarder rotation state
After a true new proxy refresh, Login resets every forwarder instance to the start of the new list.

Exact documentation says:
- write 0 to forwarder_idx*.txt;
- remove old forwarder_advance*.txt signals;
- remove old proxy_alloc.txt claims;
- subsequent forwarder reuse/spawn starts from index 0, i.e. the fastest proxy at the head of the newly sorted list.

This prevents a new session from continuing an old index into a newly reordered pool.

## 5. Important audit: runtime advance threshold is 5 minutes, not 30
The original contains contradictory static text:
- call-site logs: `lần login trước >5 phút → advance proxy` and `<5 phút → giữ proxy`;
- Login initialization serializes integer 300 directly before `_proxy_reload_threshold`;
- 300 seconds = 5 minutes;
- no 1800-second integer constant exists in the Login block;
- a stale method doc says `True nếu lần login trước cách >= 30 phút (hoặc chưa bao giờ login).`

F08 resolves this conflict as follows:
**the executable runtime threshold is 300 seconds / 5 minutes; the 30-minute sentence is stale documentation.**

This is stronger than trusting either string alone because the call-site logs and serialized runtime threshold agree with each other.

## 6. Last-login timestamps drive the 5-minute decision
`last_login_times.json` persists successful-login times across TLMTool sessions.

Before a Tool/free-proxy account starts, Login evaluates the previous successful login time:
- older than threshold / never logged in → advance proxy;
- within threshold → keep the current forwarder proxy.

On successful login, `_record_login_time` updates that store.

## 7. Multi-account port and IID mapping
Exact Login documentation:
`port = 22200 + profile_idx`.

Examples from the original:
- account/profile 1 → 22201
- profile 2 → 22202
- ...
- 22200 is reserved for the default instance.

`iid = str(profile_idx)`.

Therefore each account/profile gets its own loopback forwarder instance and its own suffixed state files.

## 8. Per-instance state files
Default instance uses unsuffixed names; multi-instance uses suffix `_{IID}`.

Recovered state families:
- forwarder_mode.txt
- forwarder_idx.txt
- forwarder_stats.json
- forwarder_pid.txt
- forwarder_advance.txt
- forwarder_pinned_proxy.txt.

Examples from original docs:
- iid='2' → forwarder_mode_2.txt
- iid='2' → forwarder_pid_2.txt
- iid='2' → forwarder_pinned_proxy_2.txt
- iid='2' → forwarder_advance_2 / idx_2
- iid='12' → forwarder_idx_12.txt and forwarder_pinned_proxy_12.txt.

Shared pool/coordination files such as proxy_working.txt, proxy_alloc.txt and proxy_bad.txt are not per-account credential stores.

## 9. Forwarder start/reuse/readiness
`_start_forwarder` exact documentation says:
- start standalone forwarder subprocess;
- if an existing forwarder is still healthy, reuse it;
- block until the forwarder is ready or has failed;
- port != 22200 or iid != None creates a separate instance with independent state files.

If a tracked PID is alive but is not listening on the expected port, Login kills it and respawns.

The frozen build can launch bundled forwarder.exe; source-mode evidence also contains forwarder.py arguments `--port`, `--iid`, `--mode`.

`_ensure_forwarder_alive` verifies the loopback listener before the game is launched. If readiness cannot be guaranteed, the game is not launched into that dead network path.

## 10. Zombie-port cleanup
Login can inspect LISTENING sockets using netstat.

Exact documentation defines a zombie as a forwarder that is still listening on the desired port but is no longer tracked by the app/PID state.

That process may be killed before spawning a replacement so two forwarders do not fight over one connection path.

## 11. Mode file changes do not require killing the forwarder
`_set_forwarder_mode` writes the forwarder mode file for the target IID.

Exact documentation says the forwarder reads the file itself, so mode changes do not require killing/restarting the process.

The standalone forwarder supports proxy/direct mode and also exposes a force-direct state file.

## 12. Private pinned proxy semantics
`_write_pinned_proxy` writes the account's fixed private proxy to forwarder_pinned_proxy*.txt.

Exact Login documentation says the forwarder rereads that file every 3 seconds so new connections use the account's intended private proxy.

Writing an empty private proxy becomes the literal `direct` state.

`_clear_pinned_proxy` removes the fixed proxy so the forwarder returns to normal free-pool round-robin behavior.

Forwarder-side semantics are explicit:
- pinned `direct` → all new connections direct;
- missing/empty pinned file → normal round-robin;
- valid private proxy → pinned-only proxy path.

Private pinned failure is **PINNED-ONLY** and explicitly says `không fallback — game sẽ tự retry`.

So a broken private proxy never silently leaks that account onto the shared free pool.

## 13. Free-proxy allocation is cross-process coordinated
The forwarder uses:
- proxy_alloc.lock
- proxy_alloc.txt
- Windows msvcrt file locking.

Exact documentation says all read-modify-write allocation operations must happen under the cross-process lock to prevent lost updates between forwarder instances.

Each allocation claim records proxy string → `(iid, timestamp)`.

Free-proxy selection:
- starts at a base index;
- atomically claims a proxy not already held by another instance;
- excludes entries on the shared bad-proxy list;
- `skip_own=True` forces selection away from the instance's current claim when a definite IP change is required;
- if the pool is exhausted, the instance may fall back to its own current claimed proxy rather than corrupting another instance's claim.

Exact claim TTL/cooldown numeric values are not assigned in F08 unless directly mapped from the function using them.

## 14. Shared bad-proxy state
`proxy_bad.txt` is a shared bad-proxy list used by all instances.

Forwarder code reads still-effective bad entries and writes failed proxies back to that shared list.

A separate PROXY_COOLDOWN_SECS/BAD_COOLDOWN surface exists, but F08 leaves their exact numeric values UNKNOWN because constant-to-name mapping is not instruction-level verified.

## 15. Selective proxying of game traffic
The forwarder is not intended to proxy every destination.

Exact architecture warning in the original:
- CDN/SDK traffic on 443 must stay DIRECT because the game's TLS1.2/h2 stack can stall through the relay;
- only GAME SERVER 103.147.34.81 ports 3001/4001 is proxied;
- version.cpp/DLL filtering must use the same 3001/4001 rule.

`forwarder_targets.txt` holds one target per line as IP or IP:port.

The original explicitly warns that an empty target set would cause the function to proxy everything and reintroduce the CDN failure.

This selective-target rule is a critical parity constraint.

## 16. Proxy connection protocols
If protocol is explicitly supplied, the forwarder tries only that protocol.

The parser/connector supports SOCKS5, SOCKS4 and HTTP CONNECT.

When protocol is auto/None, the shared connector family can try the supported protocols rather than crashing on a single type.

## 17. Forwarder advance handshake
`_advance_forwarder_proxy` does not blindly assume rotation happened.

Exact documentation:
- write the per-instance advance signal;
- forwarder increments its next index when it reads the signal;
- Login polls forwarder_idx*.txt until the index changes;
- success log confirms old → new index;
- timeout log warns the forwarder may not have received the signal.

Thus proxy rotation is a file-signal + confirmation handshake.

## 18. Current proxy reporting
`_current_proxy_str` exact documentation:
- if a pinned proxy exists, show the pinned/private proxy;
- otherwise resolve the current index into proxy_working.txt;
- supports IID-suffixed idx and pinned files.

This value is used in Login logs/UI to report the effective forwarder proxy.

## 19. Row reload behavior
The row `⇄` reload path is not just a UI refresh.

Exact original sequence from `_reload_worker`:
1. advance that account's forwarder instance to the next proxy;
2. if the account currently owns a tracked game HWND, force-close it;
3. immediately log the same account in again using the newly advanced proxy;
4. do not perform another automatic advance inside that immediate re-login.

This preserves the user's explicit request for a new IP without double-advancing past it.

## 20. Forwarder stats/UI probe
The forwarder writes forwarder_stats*.json for UI status.

Login performs TCP/probe work on a background thread and posts the result back to the main Tk thread.

Stats are used to expose progress and alive/dead state without blocking the GUI.

## 21. Stop/disconnect behavior
`_stop_forwarder` terminates a tracked forwarder and removes/handles its PID state so zombie listeners do not retain the port.

`_stop_all_forwarders` exact documentation says:
- kill the default instance and every tracked multi-instance;
- remove pinned proxy state;
- run this cleanup in a thread so GUI shutdown/update paths do not hang.

F08 preserves the E08 distinction: auto-update explicitly stops all forwarders, while forced heartbeat quit intentionally leaves the independent forwarder running.

## 22. Bundled forwarder's own auto-rotation
The forwarder helper also contains `ROTATE_INTERVAL` and an auto-rotate path independent of Login's 5-minute last-login decision.

F08 does **not** assign a numeric value to ROTATE_INTERVAL because the serialized constant-to-symbol mapping is not proven at instruction level.

This means two rotation mechanisms must not be conflated:
- Login-triggered advance based on account login age/reload;
- forwarder's own internal timed rotation.

## 23. Reconstruction contract
1. preserve proxy_working.txt as the shared free pool;
2. refresh stale pool when Login sees age >5 minutes;
3. keep the lower-level recent-refresh/concurrent-refresh suppression;
4. sort verified live proxies fastest-first;
5. on true refresh reset idx files to 0 and clear stale alloc/advance state;
6. use runtime 300-second/5-minute last-login threshold despite stale 30-minute doc text;
7. map profile index N to port 22200+N and iid=str(N);
8. keep independent per-IID state files;
9. reuse a healthy existing forwarder and kill/respawn dead-listener instances;
10. require listener readiness before game launch;
11. Tool mode clears private pin and uses coordinated free-pool allocation;
12. Proxy mode pins the row-specific private proxy and never falls back to free on pinned failure;
13. Không/direct mode remains direct;
14. preserve cross-process allocation locking and shared bad-proxy state;
15. proxy only configured game-server targets; keep CDN/443 direct;
16. advance through signal file and confirm idx change;
17. row reload advances once, closes the tracked game, then re-logins without a second advance;
18. keep forwarder stats/probe work off Tk;
19. do not invent numeric internal cooldown/auto-rotate constants that are not directly mapped.
