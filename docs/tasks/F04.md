## Canonical executable
The Login module contains the exact executable filename `Thần Long  Mobile.exe` with two spaces between Long and Mobile.exe. That spelling must be preserved.

## Folder selection
The original uses tkinter.filedialog.askdirectory with title `Chọn thư mục chứa Thần Long Mobile`. The user selects a directory, not an EXE file.

## _resolve_game_dir behavior
Original documentation says `Tự nhận diện thư mục game đúng từ thư mục người dùng chọn.` and returns `(resolved_dir | None, note)`.

The documented recognition cases are:
1. selected itself contains the executable -> use selected;
2. selected/Game contains the executable -> use selected/Game, e.g. selecting D:\ThanLongMobile_PC;
3. selected is a child inside Game, e.g. ...\Game\..._Data -> step back to the parent containing the executable;
4. scan one child-directory level, prioritizing child names containing `game`, and choose a child containing the executable.

Static constants also recover rstrip plus `\/`, failure note `thư mục không tồn tại`, and terminal text indicating the executable was not found in the selected directory. This proves trailing slash/backslash normalization and invalid-path handling.

Resolver notes include `tự nhận diện thư mục Game bên trong`, `tự lùi về thư mục cha chứa game`, and `tự nhận diện thư mục con ...`. A later string `(tự nhận diện lại)` supports a re-recognition fallback, but the exact source-level branch sequence inside `_get_exe_path` remains UNKNOWN.

## Invalid selection UI
Invalid resolution uses messagebox.showerror with title `Thư mục game không hợp lệ`. The body includes the selected path, the canonical executable requirement, and example `D:\ThanLongMobile_PC\Game`.

## Valid selection UI
Success text starts `✅ Đã chọn game thành công:` followed by the resolved path. The current locked Login screenshot shows this success row.

`lbl_game_dir` begins as `Đường dẫn game: (Chưa chọn)` and is initially hidden via pack_forget. `_show_game_dir_status` has exact documentation saying it shows the game-path status label again if hidden.

The success block also contains `_profile_btns` and state `normal`, proving valid path recognition enables path-dependent profile controls. Their visual placement and launch behavior remain outside F04.

## Persistence
Login `_load_config` contains key `game_dir`, and the Login save/config block also contains key `game_dir`. From F02/E05 this belongs to the shared Login settings lifecycle under `%APPDATA%\TLMTool\settings.ini`.

F04 verifies persistence of the resolved game directory across sessions. The exact instant at which a successful folder selection is flushed to disk is not source-visible and remains UNKNOWN.

## Launch-facing path boundary
Login has dedicated `_get_exe_path`. Open-game and login paths first require a selected game directory and then obtain a usable executable path. Recovered failures include `❌ Chưa chọn thư mục game`, `❌ Không tìm thấy ... trong: ...`, and `⚠️ Chưa chọn thư mục game hoặc thiếu exe`.

The profile-launch path carries both `exe_path` and `profile_idx`, with exact docs `Mở game với profile index (1-5).` and `Launch 1 instance via suspend+inject.` No separate per-profile game-install directory contract was recovered.

Launcher constants also include `cwd` adjacent to `exe_path` and `spawn_and_inject`; exact cwd derivation belongs to F05.

## Reconstruction contract
- preserve exact filename `Thần Long  Mobile.exe`;
- use a folder picker, not an EXE picker;
- preserve direct-selected, selected/Game, parent-recovery and one-level-child-scan recognition;
- preserve preference for child names containing `game`;
- return/use resolver note information;
- preserve invalid-selection error and success status row;
- persist `game_dir`;
- obtain executable through `_get_exe_path`;
- keep profile index separate from base install directory;
- do not hard-code the example path;
- defer actual process creation/injection to F05.
