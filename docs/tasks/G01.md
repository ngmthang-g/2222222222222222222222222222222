## 10. Shared HWND and character-info references

The Party module does **not** own a separate game-window enumerator.

Its refresh block references:
- shared `start_tab`
- shared `get_windows`
- shared `utils.get_character_info`
- `RoleName`
- PID helper `_get_pid_from_hwnd`
- `bind_window_identity`
- `unbind_window_identity`

The refresh worker is threaded, and its UI apply surface returns through Tk `after`.

Therefore the wiring boundary is:

`shared game HWND discovery → Party background refresh → shared character info → Party _member_rows UI`.

Exact enumeration rules, stale HWND replacement and refresh cadence are G02.
