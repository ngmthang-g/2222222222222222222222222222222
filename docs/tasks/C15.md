## 1. Main preview has a real `Làm mới` control

- visible text `Làm mới`
- widget state name `btn_refresh_preview`
- the same preview section also contains `Đóng hết` and `Tách rời`.

The original class contains one dedicated full-list rebuild method:
- `refresh_window_preview_list`
- exact original doc: `Làm mới toàn bộ danh sách preview DWM.`

Static constant deduplication means the exact Tk `command=` expression is not directly readable next to `btn_refresh_preview`, so C15 does not fabricate whether the button stores a direct bound method or an equivalent wrapper. The behavior target itself is fully recovered.

## 2. Main refresh is a destroy-and-rebuild of preview items

Original preview teardown helpers:
- `_clear_window_preview_list`
- exact doc: `Xóa tất cả preview items.`
- `_destroy_window_preview_item`
- exact doc: `Hủy một preview item (thumbnail + cửa sổ + frame).`

Recovered teardown resources inside the same block:
- `DwmUnregisterThumbnail`
- `dst_hwnd`
- `_destroy_dwm_dst_hwnd`
- preview Tk `frame` destruction.

Therefore the refresh path is not just a label/HP repaint. The full-list rebuild tears down old thumbnail resources/items and constructs a fresh preview list.

## 3. Rebuild uses the current game-window list

`refresh_window_preview_list` recovers:
- no-game message: `Không tìm thấy cửa sổ game, hãy mở game trước.`
- `_get_preview_columns`
- `preview_cols`
- `preview_rows`
- per-item `row` / `column` placement
- `RoleName` and `HpPercent` labels
- `DwmRegisterThumbnail`
- `_apply_dwm_thumbnail_props`
- per-item DWM destination HWND creation.

Thus after refresh the visible preview list is rebuilt from the current game HWND/cache state using the currently selected preview-column mode.

## 4. Refresh preserves the manual preview order

Original `_move_preview_item` documentation states:
`Nút ◀/▶ ... Lưu thứ tự theo hwnd → refresh sẽ giữ thứ tự sau mỗi rebuild.`

This is a critical C15 behavior:
- refresh must not silently discard the user's manual preview ordering;
- `_preview_order` is HWND-backed;
- rebuild applies the retained order to the current preview set.

## 5. Periodic maintenance can also trigger a list refresh

Original `_update_window_previews_loop` block recovers:
- `alive_hwnds`
- `valid_items`
- `need_refresh`
- `_refresh_preview_labels`
- `_update_slot_comboboxes`
- exact doc: `Vòng lặp cập nhật preview: reposition + làm mới danh sách nếu cần + refresh HP.`

Therefore there are two distinct concepts:
1. explicit full-list refresh behavior;
2. automatic maintenance that conditionally rebuilds when the tracked HWND/item set changes.

C04 already locked the maintenance cadence separately; C15 does not change those timers.

## 6. Refresh keeps the DWM architecture intact

After rebuild, each preview item again uses:
- live DWM thumbnail registration;
- a destination overlay HWND;
- frame-root geometry;
- the same click/activation path recovered in C03.

Refresh therefore recreates live previews rather than replacing them with screenshots.

## 7. Detached preview has its own refresh path

Detached control bar contains the `↺` refresh button and `_btn_detached_refresh`.

Original method:
- `_refresh_detached_preview`
- exact doc: `Đóng rồi mở lại preview — tải lại danh sách cửa sổ mới.`

Verified detached-refresh model:
`close detached preview → reopen detached preview → rebuild from the current game-window list`.

This is deliberately separate from the main embedded `Làm mới` control.

## 8. Detached refresh preserves the detached subsystem contract

- the detached DWM overlay region;
- detached control bar;
- detached grid setting;
- independent detached update loop.

Exact temporary visibility transitions of embedded previews during the close/reopen sequence remain part of the C14 unknown and are not re-invented here.
