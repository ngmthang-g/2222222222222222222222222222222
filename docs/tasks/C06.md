## 2. Common grid arranger — `_arrange_grid`

Recovered constants/names:
- `GetSystemMetrics`
- exact integer literal **450**
- exact integer literal **40**
- `min`
- `sorted`
- `TLMStartTab._arrange_grid.<locals>.<lambda>`
- `new_slots`
- `cols`
- `ww`
- `wh`

Exact original docstring:

`Xếp cửa sổ theo grid dựa trên thứ tự array.`
`Cửa sổ chính (master) luôn ở vị trí 0 (góc trên trái),`
`các cửa sổ khác xếp lần lượt theo sau.`

Verified behavior:
1. Input là danh sách game HWND + số cột/hàng.
2. Engine đọc screen metrics bằng `GetSystemMetrics`.
3. Engine tính kích thước ô/cửa sổ qua `ww`, `wh`; trong cùng function có exact literals **450** và **40** cùng `min`.
4. Engine tạo `new_slots` và cập nhật grid-slot state.
5. Master được promote lên index 0 → góc trên trái.
6. Các HWND còn lại giữ thứ tự tuần tự sau master.

### Explicit unknown — không bịa
Readable Nuitka constants chưa đủ để dựng **chính xác biểu thức toán học** kết hợp:
- screen width/height,

- `min`,
- `ww`, `wh`.

Do đó C06 **không** tự gán nghĩa “450 là width cap” hay “40 là taskbar margin” khi chưa có expression source/runtime trace. Exact x/y/w/h formula vẫn là UNKNOWN.

## 3. Common move-only engine — `_move_windows_offset`

Exact original docstring:

`Di chuyển tất cả cửa sổ game theo pos_fn(index) → (x, y), GIỮ NGUYÊN kích thước.`
`Cửa sổ chính (master) luôn được xếp ở vị trí đầu tiên (index 0).`

Recovered flow:
- `_get_preview_hwnds`
- `master`
- `wins`
- `pos_fn`
- `_reset_hidden_state`
- `_move_windows_offset`

Kết luận:
- helper này là primitive **move position only**;
- kích thước hiện tại được giữ nguyên;
- master luôn nhận `index=0`;
- vị trí mỗi HWND do `pos_fn(index)` trả về;
- state ẩn được reset trong luồng re-layout.

Binary có `SetWindowPos` và `SWP_NOSIZE`; không có literal/import `MoveWindow` trong inner EXE. Vì vậy đường bố trí phục hồi dùng SetWindowPos-family semantics, không được tự thay bằng MoveWindow.

## 4. Resize helper

Global helper `resize_window` có cùng constant block:
- `GetWindowPlacement`
- `ShowWindow`
- `SW_SHOWNORMAL`
- `SetWindowPos`
- `SWP_NOZORDER`
- `SWP_NOACTIVATE`
- `SWP_NOMOVE`

Model phục hồi:
- kiểm tra placement/trạng thái cửa sổ;
- đưa cửa sổ về normal state khi cần;
- resize bằng `SetWindowPos`;
- resize path không di chuyển vị trí vì có `SWP_NOMOVE`;
- không kích hoạt và không đổi z-order theo constants phục hồi.

Không thấy bằng chứng để thay bằng API khác.

## 7. Limit handling dùng chung

Recovered:
- `new_version_info`
- `max_windows`
- exact default/fallback literal **999** (xuất hiện 2 lần trong block)
- exact doc:
  `Lấy giới hạn số cửa sổ từ server (new_version_info.max_windows).`
- `_get_max_windows`
- `_count_game_processes`
- exact process-count doc:
  `Đếm số process Thần Long  Mobile.exe — đọc từ cache worker thread. Không spawn tasklist trên main thread (tránh treo GUI).`

Limit UI:
- `⚠️ Quá giới hạn ... cửa sổ, không thể bật đồng bộ`

Auto-stop:
- `_auto_stop_sync`
- exact doc:
  `Tắt cả layout sync và input sync khi quá limit.`

Verified:
- giới hạn runtime đến từ server field `new_version_info.max_windows`;
- có fallback 999;
- process count lấy từ worker cache;
- vượt giới hạn chặn việc bật sync;
- nếu đang sync mà vượt limit thì stop **cả layout sync và input sync**.
