## Main findings
- Receiver rows are dynamic account-only rows with delete; at least one row is always retained.
- Legacy singular receiver aliases point to the first receiver row; all rows share the single Dồn coordinate already frozen in L05.
- Receiver combobox values are rebuilt from current managed account rows. Duplicate character names are disambiguated with a parenthesized HWND display label and resolved through _receiver_hwnd_map.
- Every receiver combobox gets the same account candidate list. No cross-row uniqueness exclusion is recovered; downstream _all_receiver_hwnds returns a set, so repeated receiver selections collapse for set-based membership.
- Receiver selection changes restyle/reorder account rows; receiver names are highlighted while normal rows return to black.
- Receiver runtime ownership is in don_logic, not inferred from GUI text. Each receiver has independent registry state: ready Event, donated Event, aborted Event, donor_hwnd.
- recv_cycle is the receiver FSM: sell -> move back to receive point -> ready -> wait for donated/abort/donor death -> repeat. Registry is unregistered when the receiver cycle exits.
- GUI receiver phases are derived from that FSM: Sẵn sàng nhận, Chuẩn bị nhận, Đang nhận. _on_recv_phase('start') -> Đang nhận; 'done' -> Sẵn sàng nhận only if the row still says Đang nhận.
- Receiver priority is recomputed at selection time. _pick_ready_receiver considers ready receivers, excludes the donor itself, requires resolvable coordinates, selects the lowest current gold/hour receiver speed, and randomizes ties.
- _fallback_receiver is only a movement/manual fallback: first receiver with valid coordinates. Automatic Dồn selection does not replace a missing-ready condition with that fallback.
- Automatic donor flow waits for ready receivers, rechecks readiness after the receiver lock is acquired, skips busy receivers, and continues farming when none are ready or all are busy.
- Locking is per receiver, not global. Different donors can Dồn in parallel to different receivers; only one donor at a time may use a given receiver. Manual and automatic Dồn both use the chosen receiver's lock.
- Abort is fault-isolated per receiver. A donor stop/disconnect or dead donor window signals receiver abort/reset instead of leaving that receiver waiting forever.
- A background trade-invite watcher is one watcher per receiver. It runs outside Dồn cycles, accepts invites only from names managed by this tool, rejects unknown names, and yields while the receiver is actively claimed by a donor to avoid racing the real Dồn flow.
- Config keeps recv_count + recv_<n>_acc + recv_<n>_coord and legacy receiver/recv_coord compatibility surfaces. Current runtime coordinate remains shared. Exact precedence when conflicting legacy/per-row coordinate values coexist is still not source-visible enough to freeze and remains explicit UNKNOWN.
- Packaged runtime log contains no correlated RECV/DON receiver lifecycle trace, so live parity remains environment-required.
