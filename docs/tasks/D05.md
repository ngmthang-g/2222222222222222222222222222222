# D05 — Strings/constants mapped by TLM module

## STATUS
**VERIFIED_EXACT_MARKER_BLOCK_MAP_WITH_HEURISTIC_SIGNAL_CLASSIFICATION**

D05 maps printable constants/strings from the frozen inner EXE to each TLM internal module that has an exact Nuitka `<module NAME>` marker.

Frozen inner EXE SHA-256:
`15c8044f215680d6851c8f901a5dc7d181068d91a8938f2a628077cf21a2df22`

## 1. Mapping method

For each of the **37** exact-marker TLM internal modules:
1. locate the exact module marker;
2. define its compiled constant/string block up to the next valid exact module marker;
3. retain every GNU-strings printable constant with absolute EXE offset;
4. normalize one leading Nuitka type/tag byte only for display;
5. classify high-signal strings into:
   - `API_CONST`
   - `LOG_UI`
   - `PATH_FILE`
   - `URL`
   - `SYMBOL`
   - `UI_TEXT`.

This uses the same conservative block boundary model as D02.

## 3. Why high-signal classification is heuristic

The mapping from **offset → exact compiled marker block** is deterministic.

The label `high-signal` is a convenience filter, not a semantic proof. It searches for patterns such as:
- WinAPI-like names and Windows message constants;
- log/UI-looking text;
- paths/file names/URLs;
- meaningful function/state symbols.

A string being inside a module block proves compiled-block locality under this marker model. It does **not** by itself prove:
- exact original source line;
- exact call site;
- that the string is user-visible;
- that every dependency-injected/library constant originated in the author's source file.

## 4. Important block-size observation

Most TLM module blocks are compact, but `info_tab` spans a much larger marker interval:
- raw strings: **217,581**
- high-signal rows: **20,328**

This is a property of the compiled marker layout, not evidence that the original `info_tab.py` source literally contained all those strings. The interval can contain compiler/runtime/dependency material until the next exact module marker.

Therefore D05 preserves offsets and block provenance rather than pretending that every interval string maps one-to-one to a Python source statement.

## 7. Reconstruction value

D05 gives later tasks a searchable provenance map for:
- UI labels and status messages;
- config/file keys;
- HWND/WinAPI operations;
- network URLs;
- cross-module helper symbols;
- failure/log strings;
- hidden or dormant feature clues.

Later per-feature reverse engineering should use these offsets together with D02/D04 relationships and local symbol context instead of relying on global string search alone.

## 8. Full output policy

The committed extractor can emit:
- `D05_MODULE_STRINGS.tsv.gz` — all raw rows;
- `D05_HIGH_SIGNAL_STRINGS.tsv.gz` — classifier-selected rows.

To avoid committing a very large duplicate evidence blob at this checkpoint, the repo stores:
- per-module deterministic counts;
- representative exact-offset samples;
- the reproducible extractor.

A later task can materialize the full compressed output without changing the extraction rule.
