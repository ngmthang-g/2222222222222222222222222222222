## 1. Auto is the default Start mode

Original constants in TLMStartTab recover:
- mode state: mode_var
- internal value: auto
- visible label: Auto
- other mode internal value: sync
- visible label: Xếp lưới
- both Radiobuttons dispatch to _on_mode_change.

The initialization constant order places auto immediately before mode_var, consistent with the visible screenshot in which Auto is selected.

## 2. Exact mode-change contract

Original _on_mode_change documentation:

Hiện/ẩn frame tương ứng với chế độ được chọn.
Chọn sync → tự kích hoạt đồng bộ cửa sổ + phím chuột.
Chuyển sang auto/manual → tự tắt cả 2.

Therefore mode sync is the Xếp-lưới side, while Auto/manual disables both layout sync and input sync.

## 3. Entering sync stops conflicting automation

The mode-change block contains:
- farm_tab_ref._is_farming / _toggle_farm and log: [MODE] Chuyển Đồng bộ → dừng Train
- daily_tab_ref._punish_running / _punish_toggle and log: [MODE] Chuyển Đồng bộ → dừng Trừng ác
- daily_tab_ref._treasure_map_running / _treasure_map_toggle and log: [MODE] Chuyển Đồng bộ → dừng Tàng bảo đồ.

This establishes the mode boundary: Auto is not the layout/input synchronized state.

## 4. Auto reset geometry is exact: (0,0), 1366×768

Inside the original mode-change block:
- auto
- get_windows
- serialized integer 1366
- serialized integer 768
- exact log: [MODE] Chuyển Auto → đã đưa cửa sổ về (0,0) 1366x768
- error log: [MODE] Lỗi reset cửa sổ: ...
- followed by _auto_tile_loop.

A second constants block contains serialized 1366, 768 immediately before resize_window. C07 therefore verifies the Auto transition reset target: game windows are returned to origin (0,0) at 1366×768 before/around the Auto tiling cycle.

## 5. Auto tiling loop is real

Original state:
- auto_tile_active
- _auto_tile_id

Original methods:
- _toggle_auto_tile
- _auto_tile_windows
- _auto_tile_loop

Exact docs:
- Bật/tắt vòng lặp xếp ngói tự động.
- Vòng lặp 1 giây sắp xếp lại cửa sổ.
- Chỉ chạy khi auto_tile_active = True.

Therefore Auto tiling is recurrent with a documented 1-second re-arrangement interval. The 1.5-second cadence found in the C06 audit is input-sync keepalive and is unrelated.

## 6. Ordering rule: RoleName sort + master first

Exact _auto_tile_windows documentation:

Xếp các cửa sổ game theo kiểu xếp ngói, sort theo tên nhân vật.
Cửa sổ chính (master) luôn ở vị trí đầu tiên.

Recovered local evidence includes _sort_key, sort, key, ci and RoleName. Combined with C02/C05, the ordering model is:

current game HWNDs
→ character-info cache
→ sort by RoleName
→ master HWND forced to first position
→ auto-tile placement.

C06 already proved the server source new_version_info.max_windows, fallback 999 and worker-cached process count. Auto tiling therefore uses the same runtime limit subsystem.
