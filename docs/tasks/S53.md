## Reproduced S52 stop() bug
- S47 stop(timeout) used a single absolute deadline for acquiring \`_lifecycle_lock\` and \`thread.join()\`, **but then entered \`with self._lock:\` with NO timeout**.
- Background Event.wait(20) worker can exit promptly on cancellation, while an **independent** \`poll_once()\` called from another test-owned thread still owns \`_lock\` inside a blocked injected \`_now()\`. A stop joins the real worker but hangs indefinitely waiting for the independent poll lock, violating its caller-specified timeout. F09ReadOnlyTabLifetime.finish_close(timeout) delegates to worker.shutdown(timeout) and inherits this defect.
- Deterministic test-first repro: start true 20-second worker, start independent poll holding _lock, call stop(0.035), shutdown(0.035) or finish_close(0.035) from another thread; assert returned within .28 s before releasing poll.
