- `src/login_running_process_capacity.py`: `NativeWindowsProcessImages.process_images()` uses actual Win64 `CreateToolhelp32Snapshot(TH32CS_SNAPPROCESS)`, `Process32FirstW/Process32NextW`, `CloseHandle`; outputs native PID and Unicode image base name **read-only**. `count_current_game_processes()` validates snapshot identities and counts **distinct PIDs** whose image basename matches original `EXE_NAME` (**`Thần Long  Mobile.exe`**, TWO spaces) case-insensitively, even without a visible HWND. Closes native snapshot handle even on errors and fails closed if a process listing could not be trusted. `PROCESS_SNAPSHOT_KIND` explicitly notes Toolhelp is **NOT verified as the original API**.
- `check_native_open_game_capacity(snapshot,game,verified_emulator_sessions=...,backend=...)` invokes the **existing S26 preflight first** with unknown count, to reject unverified/blocked Info, missing Login permission and invalid plan limit **BEFORE native enumeration**. Requires an explicit external nonnegative **integer** emulator session count; missing/unknown/bool/negative does **not silently mean zero**. Then combines *actual native EXE count + externally supplied verified emulator count* and calls **unchanged S26 original `extra=1` preflight**. Returns a diagnostic `S160RunningCount` separated from S26's `LaunchPreflight`. It never launches game, creates HWND or grants any license; an authenticated emulator count provider and actual signed Info issuer are NOT available in production.

Copies *Windows standard `cmd.exe`* into **TWO separate temp dirs** with the **exact original Unicode image name**, then starts only those owned images with benign bounded ping; actual Toolhelp snapshot verifies two distinct owned PIDs and combined S26 extra-one preflight denies a third when plan limit=2.
