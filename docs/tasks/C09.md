# C09 — Preview columns 1x–5x

## STATUS
**VERIFIED_WITH_EXPLICIT_UNKNOWNS**

Evidence integrity:
- original archive and inner EXE hashes remain the locked Gate-A specimen;
- Xếp-lưới screenshot hash remains f1573668b94667e85b380326dcb5a4fc1a8cbc723d9cee80e6335c13961c339a.

## 1. Main preview column control is explicit 1x–5x

Build-ui constants recover the visible sequence:
- Cột:
- 1x
- 2x
- 3x
- 4x
- 5x
- _set_manual_preview_grid.

The control is backed by preview_grid_var.

Original initialization constants show preview_grid_var default value = 2x.

The current screenshot independently shows 2x selected.

## 2. Manual-grid selection is a real callback

Original method documentation for _set_manual_preview_grid:
Chọn chế độ lưới thủ công cho preview.

State also includes preview_grid_manual, so the tool distinguishes an explicit user/manual preview-grid choice from the rest of preview state.

Exact source-level assignment order for preview_grid_manual is not directly visible and remains explicit UNKNOWN.

## 3. Column count is parsed from the selected x-value

Recovered _get_preview_columns constants:
- default/fallback visible constant 2x
- replace
- exact doc: Xác định số cột preview.

This strongly establishes that the selected string form such as 2x is parsed/normalized to a numeric preview column count rather than being decorative text.

## 4. Preview list rebuild consumes preview_cols and preview_rows

refresh_window_preview_list recovers:
- _get_preview_columns
- preview_cols
- preview_rows
- grid_columnconfigure
- row
- column
- per-preview frame construction
- DWM thumbnail registration.

Therefore changing 1x–5x changes the Tk preview grid's column count and causes preview items to be laid out by row/column before their DWM destination windows are positioned over the preview frames.

### Explicit unknown
The exact source arithmetic used to compute preview_rows from item count and preview_cols is not directly recovered. It is not guessed.

## 5. Current 2-column geometry is independently measured

Gate-C C03 measured the current 3-item / 2-column preview state:
- 3 visible preview items
- layout: 2 columns, first row has 2 items and second row has 1
- each outer preview frame: 205×137 px
- visible black preview surface: 197×110 px.

This geometry is valid for the captured 2x state only. C09 does not extrapolate exact pixel widths for 1x, 3x, 4x or 5x without runtime screenshots.

## 6. Preview order is independent from column count

Recovered _move_preview_item documentation:
Nút ◀/▶ trên header preview: đẩy cửa sổ này lên trước (delta=-1) hoặc sau (delta=1).
Lưu thứ tự theo hwnd → refresh sẽ giữ thứ tự sau mỗi rebuild.

Thus:
- 1x–5x controls the number of preview columns;
- ◀/▶ controls the logical HWND preview order;
- rebuild preserves that order.

Column changes must not silently re-sort preview HWNDs by name.

## 7. DWM preview remains live

C03 already proved each preview item is a live DWM thumbnail, not a static screenshot.

C09 therefore changes preview layout only; it does not replace the capture/render pipeline.

## 8. Main preview and detached preview use separate column state

Detached preview has its own recovered controls/state:
- label Cột
- readonly Combobox
- _detached_cmb_cols
- detached_grid
- separate detached control bar.

Recovered settings.ini block persists:
- grid_cols
- grid_rows
- detached_auto_open
- detached_grid.

No preview_grid / preview_grid_var key is present in that recovered settings block.

Therefore:
- main 1x–5x preview selection is classified runtime-only from current evidence;
- detached preview column selection uses separate detached_grid state and is persisted.

Recovered detached_grid default constant is the string-like value 3.

## 9. Update/rebuild integration

C04 already recovered the preview maintenance loop:
- normal preview update cadence 800ms/2000ms depending on count threshold;
- 60ms resize reposition debounce;
- conditional list rebuild;
- DWM image itself remains compositor-driven.

When the main grid is rebuilt, DWM destination windows are repositioned to the new preview-frame geometry.
