## 2. Comparison classes

### S0 — STRICT_RASTER
Use for:
- client geometry
- tab-strip geometry
- group/frame lines
- large flat fills
- custom colored-button fills
- structural separators
- control outer rectangles where B03–B12 measured them

Pass:
- geometry: **0 px drift** for locked structural coordinates
- flat interior fill: **exact RGB**
- one-pixel structural line: exact coordinate and exact locked RGB

### S1 — STRICT_GEOMETRY_NATIVE_RENDER
Use for:
- ttk comboboxes
- entries/spinboxes
- check/radio indicators
- native scrollbar track/thumb

Pass:
- outer control geometry: exact where measured
- common dimensions must match B13
- stable flat field/border pixels should match
- native arrow/check glyph anti-aliasing may differ by **±1 px envelope** and is not compared RGB-for-RGB

### T1 — TEXT_ENVELOPE
Use for text.

Pass:
- correct text/content for static strings
- correct Segoe UI family/normal-vs-bold role
- text anchor/bbox envelope within **±1 px**
- glyph-height class must match B13
- do not fail solely on ClearType subpixel fringe RGB

Numeric source font point sizes remain UNKNOWN; visual raster parity is the criterion.

### D1 — DYNAMIC_CONTENT_MASK
Use where the screenshot contains machine/server/runtime/live data.

The dynamic pixels are excluded from strict content equality, but the following remain strict:
- container rectangle
- field/background color
- label
- surrounding alignment
- text/graph region allocation

Examples:
- CPU percentage/history plot
- device-derived application ID
- server changelog/price/catalog
- account/character names
- HP/status text
- selected/persisted config values when not proven clean defaults

### C1 — CURSOR_MASK
Mouse cursor pixels are excluded from comparison. Underlying control geometry is checked from another unobscured capture or from the measured region.

### N0 — NONCLIENT_EXCLUDED
Titlebar/window-frame pixels are not Gate-B pass criteria because Windows theme/DPI rendering is environment-specific.

## 6. Pass/fail order for later pixel tests

1. **Normalize to client region** (except Party raw-region rules).
2. Verify client size and notebook geometry.
3. Verify selected tab.
4. Verify group/frame bounds.
5. Verify control bounds.
6. Verify exact semantic flat fills.
7. Verify static text content and T1 envelopes.
8. Apply C1 cursor masks.
9. Apply D1 dynamic masks.
10. Report remaining mismatched pixels by region/class, never as one undifferentiated whole-window score.

A page cannot pass because its total mismatch percentage is low if a locked structural coordinate or semantic color is wrong.
