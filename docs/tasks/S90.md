- If real externally supplied `read_role(hwnd,pid)` is unavailable, the roster may track real physical HWND/PID but produces **NO ready character names** (`ROLE_READER_UNAVAILABLE`); NEVER substitutes the window title, test names or fake RoleID.

Ambiguous duplicate character names are excluded from config-ready name list; previously selected names hidden from ready selection.
- `PartyRoster.apply(result, fresh_start_snapshot)` rechecks snapshot **revision and (HWND,PID) generation** on the Tk owner thread; on changed PID, vanished window or invalid cache discards stale data, never lets a delayed worker rename a replacement game account.
- `TkPartyRosterRefresh` schedules Party consumer scans via **actual Tk after(3000)**, only calls the already registered Start producer's `read_snapshot` without starting another producer, and performs optional external reader work in a daemon thread. The background reader NEVER manipulates Tk. Tk consumes immutable results from a queue at conservative **100ms** polling; exact original worker→Tk handoff delay is still UNKNOWN and **100ms is a local implementation choice, NOT a claim of original parity**.
- Initial refresh is scheduled after 3000ms because original first-tick timing is UNKNOWN, not because this start offset is proven. Cancellation/shutdown invalidates generation and Tk after tokens; old worker results cannot repopulate stopped/restarted tab. Final S90 safety revision prevents two external RoleName reader threads overlapping after rapid stop/start if an earlier reader is blocked.
