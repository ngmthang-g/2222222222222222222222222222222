## 1. UI callback
Original Auto UI recovers:

## 2. Exact original behavior
Original EXE doc:
Xếp chéo: chồng lưới lên nhau, gốc (0,0), mỗi cửa sổ lệch +50 x và +50 y.

This provides the exact positioning rule.

## 3. Per-index formula
Through the shared _move_windows_offset(pos_fn) engine:
- master is index 0
- remaining windows follow in current ordered HWND list
- index 0 → (0,0)
- index 1 → (50,50)
- index 2 → (100,100)
- and so on, +50 X and +50 Y per index.

## 4. Size and API behavior
The shared movement helper explicitly keeps current window size.

C06 recovered SetWindowPos-family movement and did not recover a MoveWindow literal/import. Therefore Xếp chéo is position-only; it must not resize windows.

## 5. Hidden-state integration
The shared movement path invokes _reset_hidden_state.

If windows had been pushed off-screen by Ẩn hết, re-layout clears the hidden bookkeeping because windows are placed back at visible coordinates.

## 6. Runtime completion path
The shared helper emits:
[Xếp] Đã xếp ... cửa sổ

so the command performs an actual multi-HWND action.

## 7. Mode/concurrency boundary
Xếp chéo is built inside auto_frame. C07 proved Auto can maintain a 1-second tile loop when auto_tile_active=True.

The exact priority if Xếp chéo is invoked while that loop is already active is not exposed by static evidence. Immediate +50/+50 diagonal placement is VERIFIED; later retile behavior in that concurrent state remains UNKNOWN until Windows runtime tracing.
