## Reproduced S49 source defect
- \`src/login_schedule_worker.py::_start_locked()\` calls native Python \`threading.Thread.start()\`.
- Its existing exception handler caught \`RuntimeError\` **only**, despite native thread initiation being able to fail with \`OSError\` (including \`PermissionError\`) when host/system thread creation fails.
- Under injected deterministic \`Thread.start -> OSError\` on untouched source, the exception propagates outside \`start()\` while \`_cancel\` is CLEARED, \`_clock\` enabled, \`_thread\` points to an unstarted worker and \`status\` falsely states EVALUATING_ONLY_NO_ACTIONS. This is a real local safety/reliability defect in reconstructed code (not a claim of original binary's exact failure status).

## Narrow production fix
- ONE source module: \`src/login_schedule_worker.py\` catches \`(RuntimeError, OSError)\` at thread start. On either error it restores \`_cancel.set()\`, disables/clears clock, clears the unstarted worker reference, returns False and reports BLOCKED_THREAD. If one-way shutdown was already requested, CLOSED takes priority.
- Unchanged: normal Thread.start path, 20-second Event.wait, S47 timeout, S48 multi-stopper fence, S49 shutdown fence, S45 Tk lifetime, F02/F09 settings, original ZIP, PLAN, all game-dependent behaviors. No broad catch that might conceal arbitrary programming failures.
