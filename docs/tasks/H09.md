## 1. Pickup/keep-mode UI is a keep policy, not a direct pickup toggle

The Train UI label is:

`Lọc đồ giữ lại:`

The frozen shared bag-filter constants define exact modes:

- internal `none` → visible `Không`
- internal `weapons` → visible `Chỉ vũ khí`
- internal `all` → visible `Tất cả`

Exact constants:
- `KEEP_MODES = ('none', 'weapons', 'all')`
- `KEEP_MODE_DEFAULT = 'all'`

B05 shows `Tất cả` selected, matching the static default.

This radio controls what the Train discard filter is allowed to throw away. It is separate from the actual in-game pickup enable switch handled by `pickup_no_cankhon`.

## 2. Exact keep-mode → preset-key mapping

The frozen `KEEP_PRESET_KEYS` structure is:

- `none` → `['discard_weapons', 'discard_nonweapon']`
- `weapons` → `['discard_nonweapon']`
- `all` → `[]`

FarmTab wrapper documentation is exact:

`Radio Nhặt đồ → preset keys bag_filter (train).
        [] = không vứt gì. Worker farm dùng với discard_for_activity.`

Therefore:

### Không / none
Keep no equipment category represented by the Train filter:
- discard weapon preset;
- discard non-weapon-equipment preset.

This must **not** be misread as “delete every item in the bag”. Train's keep-mode mapping does not automatically add medicine/material discard presets.

### Chỉ vũ khí / weapons
- keep weapons;
- discard the Train non-weapon-equipment preset.

### Tất cả / all
- preset-key list is empty;
- no discard rules are selected by this keep-mode filter.

## 3. Weapon classification is explicit and protected by default

The shared `bag_filter` rule contract says:

- `match_weapons=True` means match only weapons through `weapon_ids`;
- weapon discard is the explicit exception to the normal protection rule;
- `allow_weapons=False` means weapons are not discarded by default;
- `protect_ids` / `protect_names` have highest protection priority.

The Train preset key:
- `discard_weapons`
uses the explicit weapon-matching rule.

Shared memory/item metadata also exposes:
- `weapon_ids.is_weapon`;
- `NON_WEAPON_EQUIP_TYPES`;
- metadata `src/type` information.

Thus “Chỉ vũ khí” is implemented by **discarding non-weapon equipment while leaving weapons protected**, not by guessing weapon status from UI text.

## 4. Train non-weapon filtering depends on item metadata

The shared bag-filter startup warning says:

`meta trong ... loc non-weapon se rot het, chi con vu khi (ID) vut duoc`

when the metadata file/data is unavailable.

This proves the non-weapon path depends on item metadata / equipment-type classification.

It is not a simple “anything whose ItemID is not a weapon ID” rule over the entire bag.

Stage-S reconstruction must preserve the metadata-based non-weapon-equipment boundary.

## 6. Shared discard_for_activity contract

Exact shared documentation:

`Chay cac preset duoc tick cua 1 hoat dong.
    keys: list key preset duoc chon (None/[] -> KHONG vut gi).
    extra_rules: rules bo sung ngoai preset (tuy chon).`

The shared bag-filter module also locks:

- empty rules → zero result;
- do not scan memory;
- do not send item packets;
- multiple active presets are OR-combined;
- targets are deduplicated by `dbID`;
- one send pass is used.

This is why `Tất cả / all` is a real no-discard mode, not a hidden default preset.

## 7. Exact discard primitive and destructive scope

The bag-filter module exact documentation says:

`Vut la mat het ca chong (packet 100005 "4:dbID")`

The shared item action layer also identifies packet **100005** for abandon/delete-by-dbID action 4.

Therefore one discard target means:
- the target inventory instance is identified by `dbID`;
- the abandon action removes the whole stack represented by that dbID;
- the filter does not decrement quantity one item at a time.

This behavior is downstream of the keep-mode decision.
