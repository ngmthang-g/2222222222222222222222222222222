## 4. Auto-train enable path is shared `utils.start_auto_train`

Daily's combat block directly references `start_auto_train` and passes the keyword-name tuple:

```text
(stop_check, verify)
```

The shared helper's frozen defaults are exactly:

```text
stop_check=None
verify=True
samples=3
interval=1.0
retries=2
```

This means the helper itself can perform at most **3 send attempts** by default.

Its exact behavior is to send game auto mode **Train (mode 1)** and, when verification is enabled, read `Direction` every 1 second for 3 samples:

- at least one valid direction change → verified success;
- all valid samples equal → verification failure;
- too few valid memory samples → `None`, deliberately fail-open;
- send/verification failure can retry up to two times.

The exact Boolean value supplied by Daily for its explicit `verify` keyword is not instruction-bound by the constants stream. K06 records the keyword and helper default but does not invent that call argument.

## 9. `_wait_movement_stopped` boundary is now corrected and frozen

The helper's recovered locals are:

```text

_stopped, ok, hung_deadline, recovered, md
```

Its immediately associated defaults are `(None, None, False)`, so the recovered `by_memory` default is **False**.

When the memory branch is used, Daily calls `utils.wait_stopped_by_direction` with explicit timeout **300 seconds**. The shared helper exact defaults are:

- timeout = 300 s;
- stable_needed = 6;
- interval = 0.5 s;
- move_eps = 16 pixels.

Shared frozen documentation specifies two phases: wait for `common.active` + a valid/stable MapID, then poll `PosX/PosY/MapID`; map change or movement beyond 16 px resets stability; 6 stable polls (~3 s) means stopped; stop/timeout returns False.
