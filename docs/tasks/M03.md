## Key conclusions
- RAO_DEFAULT_CHANNEL is Thế giới, therefore default ID is 8.
- Rao is a 7-channel subset of memory_items.CHAT_CHANNELS. Shared extra channels Đặc biệt/9, Nói thầm/7, Liên máy chủ/10 are not exposed by Rao.
- M02 persistence field channel stores the display-name string, not the integer ID.
- _resolve_rao derives channel_id at runtime and returns (content, interval_seconds, channel_id, channel_name).
- memory_items.send_chat exact argument surface is (hwnd, channel_id, content).
- Rao _slot_loop carries content/interval/chan_id/chan_name then calls MI.send_chat; do not pass the Vietnamese name as the packet channel.
- Shared packet code uses G_TCPPacketDefine.CMD_CLIENT_CHAT, Base64 content and numeric Channel.
- Successful normal Rao send must resolve through the current RAO_CHANNELS mapping.
- Exact UI/load normalization of a non-empty stale/retired channel name remains UNKNOWN; do not invent a replacement ID.
- Missing/empty row creation follows RAO_DEFAULT_CHANNEL, but the precise load-vs-add defaulting layer remains unknown.
- Frozen runtime log contains no correlated Rao send/channel trace, so live echo parity remains runtime-required.
