## 2. Duration is a combat-duration setting, not a run-count setting

The runtime workers carry `punish_duration` directly into the Trừng Ác execution sequence.

The activity worker logs:

`[TRỪNG ÁC] Worker bắt đầu — move=<...>, thời gian đánh <...>`

There is:
- an internal `loop_idx`;
- runtime log `[TRỪNG ÁC] Lần <...> — ...`;
- no visible repeat-count widget;
- no `daily_punish_repeat`, `punish_repeat`, `repeat_count` or `max_repeat` config symbol in the exact Daily payload.

Therefore Trừng Ác is not a user-configured N-run scheduler. The outer worker is an open-ended loop controlled by stop/live/activity conditions, while `punish_duration` is the per-cycle combat-time parameter passed down to the execution sequence.

`_validate_repeat` exposes digit-oriented validation through `isdigit`; despite its generic name, K03 does not reinterpret the duration entry as a repeat counter.

Exact empty-edit/min/max validation expression is not instruction-bound and remains a UI microdetail.

## 6. Four different Trừng Ác ownership surfaces

The exact top-level architecture has four distinct entry/worker roles.

### `_punish_start_worker`
Exact doc:

`Nút Bắt đầu (Trừng ác): inject trước rồi bật quy trình.`

This is the activity-level start wrapper:
- ensure/inject game windows first;
- then enter the Trừng Ác activity toggle.

### `_punish_toggle`
Owns activity-wide batch state:
- `_punish_running`
- `_punish_cancel`
- activity-level run button state.

Its frozen constant block contains:
- stopping: `Đang dừng...` + `disabled`
- running: `Dừng lại` + `FireBrick`
- launch target: `_punish_run_worker`.

### `_punish_run_worker`
This is the activity-wide batch worker:
- collects rows currently selected as Trừng Ác;
- snapshots selection/process identity;
- runs loop iterations across the selected account set;
- terminates when cancelled or no eligible active account remains.

### `_punish_single_worker`
This is the one-row session worker used by K02's per-row/all-account coordinator:
- receives one HWND/row;
- snapshots that row's generation;
- owns its own `loop_idx`;
- uses `_GenStop` with the row's real stop Event + generation.

These are not interchangeable.

## 9. Live filtering is repeated inside the batch loop

The worker has exact terminal logs:

- `[TRỪNG ÁC] Không còn acc nào sống — dừng`
- `[TRỪNG ÁC] Tất cả <N> acc đã dừng — tự động dừng`.

And locals:
- `alive`
- `still_active`.

Therefore the start-time selection is not blindly reused forever.

Each outer iteration filters the snapshot into:
1. accounts whose window/process identity is still live;
2. accounts that are still logically active.

If no live account remains, the activity worker stops.
If all selected accounts have stopped their row/activity session, the activity worker auto-stops.

Exact list-comprehension/source syntax is not recovered, but this two-stage semantic filter is directly reflected by the locals and distinct terminal logs.

## 13. Activity-wide batch worker versus K02 bottom all-account coordinator

These are separate orchestration modes:

### Activity-wide Trừng Ác batch
- selects only rows currently configured as Trừng Ác;
- owns `_punish_running/_punish_cancel`;
- uses `_punish_run_worker`;
- activity-level button uses Trừng Ác/Dừng lại/Đang dừng states.

### Daily bottom Bắt đầu
- iterates all eligible rows;
- each row may be Trừng Ác **or** Tàng Bảo Đồ;
- launches one `_punish_single_worker` or `_treasure_single_worker` per row;
- uses row Event/generation semantics and the shared Daily all-account monitor.

Do not collapse these into one global worker during reconstruction.
