## 2. High-level semantics of the three modes

The frozen farm-cycle block contains a two-value compatibility tuple:

`("full_bag_timer", "full_bag")`

used around the bag-stop path, plus direct no-town logs:
- `túi đầy (... ô, Không về) → lọc`
- `lọc xong vẫn đầy (... ô) → ở lại (Không về)`

and the common Farm-cycle state carries:
- `loop_minutes`
- `elapsed`
- `sleep_time`.

The verified mode boundary is therefore:

### never
Automatic return-town is disabled.

If the bag becomes full, the runtime may still run the pre-town loot filter, but if it remains full the direct log says the account stays in place because the mode is `Không về`.

The exact full-bag threshold/filter algorithm is H03.

### full_bag_timer
This is the current bag-enabled timed mode behind the visible `Khi đầy túi` radio.

The bag-full watcher is active for this mode, and the same common farm-cycle timer variables remain part of the loop. Bag-full can therefore terminate the wait early and cause a town cycle.

Exact bag threshold and timing constants remain H03/H04.

### cycle
This is the normal periodic mode selected by `Theo chu kỳ (phút)`.

It uses the configured `loop_minutes` cycle without the bag-full early-stop branch used by `full_bag_timer`.

Exact periodic scheduling/wait execution is H04.

## 3. _on_town_condition_changed does not own panel gating

Exact original documentation:

`Khi chọn điều kiện về thành — lưu config.`

This method is the radio-change persistence hook.

No separate town-body visibility or condition-dependent Spinbox state transition is recovered from this method.

Therefore:
- changing `never/full_bag_timer/cycle` does not itself show/hide the lower town body;
- `loop_spin` remains present in the condition row;
- the selected cycle-minute value is retained even when another mode is selected.

Permission gating can still disable controls globally, but that is H01/shared permission behavior, not return-town mode logic.

## 7. Dungeon / lock_town global UI gate

Exact original documentation for `_update_dungeon_town_lock`:

`Nếu bất kỳ acc nào chọn map khóa về thành (route có "lock_town") → ép 'Không về thành' + disable radios.`

The method's direct constants/locals include:
- `farm_var`
- `_preset_to_vars`
- `TRUYEN_DAI_LY_ROUTES`
- `lock_town`
- `has_dungeon`
- `disabled`
- `normal`
- `state`
- `never`.

Thus the gate is driven by the **selected Train preset/route of the account rows**, not merely by the currently displayed game map.

If any selected route is marked `lock_town`:
1. global `town_condition_var` is forced to `never`;
2. the return-town condition radios are disabled.

When no selected account requires the lock:
- radio state returns to `normal`.

No separate previous-condition memory field is recovered. Therefore no automatic restoration of the former `cycle/full_bag_timer` selection is statically evidenced; after unlock, the controls are re-enabled and the forced `never` value remains until changed by the user/config path.

This exact restore edge should be retained as a runtime parity check, but reconstruction must not invent a remembered previous mode.

## 12. loop_minutes relationship

`loop_minutes` is persisted independently of the selected return-town mode.

The Spinbox is visible in the condition row and is not part of the default-hidden `_town_body`.

No condition-change state transition is recovered that clears or disables its value.

Therefore switching:
- cycle → never
- cycle → full_bag_timer
- or lock_town → forced never

does not destroy the configured minute value.

That retained value is available again if `cycle` or the bag-enabled timed mode is later selected.

Actual timer execution is H04.
