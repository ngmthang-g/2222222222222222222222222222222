## 5. Toggle lifecycle is exact

Frozen toggle documentation proves:

1. ON while at least one Trừng Ác account is running:
   start the discard worker immediately.

2. ON while nothing is running:
   retain the armed setting and wait;
   a later Trừng Ác account start creates the worker.

3. OFF:
   stop the worker immediately.

4. Worker checks the checkbox again every worker cycle.

5. Toggle saves config.

Therefore the checkbox may remain persisted ON while no discard thread is alive.

## 7. Periodic worker is run-scoped, not quest-cycle-scoped

Exact worker documentation says it runs every DAILY_DISCARD_POLL seconds while Trừng Ác accounts are active.

This makes it session/run-scoped:
- it can span multiple quest/combat cycles;
- it is not a one-time post-combat action;
- when the last eligible account is gone, the worker no longer has a live run scope;
- if the setting stays enabled, a future Trừng Ác start can create a new worker.

The symbol DAILY_DISCARD_POLL is proven, but its numeric value is not safely native-instruction-bound. It remains EXPLICIT_UNKNOWN.

## 8. Parallel-account architecture

Exact worker documentation states:
- discard for all active Trừng Ác accounts in parallel;
- one child thread per account;
- packet actions inside an account are paced at 1 second;
- doing every account sequentially would bottleneck.

Worker locals include:
- inflight
- started
- hwnd
- th
- t

Thus account-level fanout is parallel.

## 9. Per-account inflight guard

Exact documentation says an account whose previous discard has not finished is skipped for the current tick, so passes do not overlap.

Therefore if one account's previous pass is still running when the next poll arrives:
- do not launch a second pass for that account;
- other eligible accounts may still run.

Do not remove this guard.

## 16. Retry/failure behavior
