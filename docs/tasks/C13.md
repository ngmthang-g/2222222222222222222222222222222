# C13 — Đóng xem

## STATUS
**VERIFIED_WITH_EXPLICIT_POST_CLOSE_UI_UNKNOWN**

## 1. Đóng xem belongs to detached preview, not game-window shutdown
Original detached-preview control-bar constants recover:
- Hủy tách
- Đóng xem
- _build_detached_control_bar.

Original detached close method documentation:
Đóng toàn bộ cửa sổ tách rời. user_initiated=True khi người dùng bấm nút đóng.

Therefore Đóng xem is a preview-view close action. It must not be implemented as closing/killing game HWNDs.

## 2. Detached-preview state is separate
Recovered runtime state:
- detached_active
- detached_items
- _detached_bar
- _detached_grid_var
- detached label visibility state.

Closing the detached view acts on this detached-preview subsystem, not on the discovered game-window set.

## 3. Detached preview is real DWM overlay windows
Original open method doc:
Mở các cửa sổ overlay DWM thumbnail trong vùng:
x=0, y=768 → đáy màn hình; rộng screen_width - 450.

Thus the detached view is not a Tk-only list; it contains actual DWM destination overlay windows.

## 4. Close method is the real teardown boundary
Recovered method:
- _close_detached_preview.

Shared preview teardown evidence from C03 includes:
- DwmUnregisterThumbnail
- _destroy_dwm_dst_hwnd / DestroyWindow
- frame/item destruction.

The detached close method's doc says it closes all detached windows, so C13 classifies it as the teardown boundary for detached DWM view resources.

## 5. User-initiated close is distinguished
The _close_detached_preview documentation explicitly has user_initiated=True when the user presses the close button.

This means the released tool distinguishes a user click from internal/programmatic closure such as app shutdown, mode changes or refresh/reopen paths.

Exact secondary state changes performed only in the user_initiated branch are not readable from the static string evidence and remain UNKNOWN.

## 6. Refresh is different from Đóng xem
Original _refresh_detached_preview doc:
Đóng rồi mở lại preview — tải lại danh sách cửa sổ mới.

So refresh intentionally closes and reopens the detached preview. Đóng xem is the terminal close action for the current viewing session, not refresh.

## 7. Hủy tách is different from Đóng xem
The detached control bar exposes both Hủy tách and Đóng xem, so they cannot be collapsed into one reconstructed button.

Static evidence proves they are distinct visible actions. Exact post-action embedded-preview visibility differences between the two callbacks are not fully recoverable from readable constants and remain explicit UNKNOWN for later Windows runtime tracing.

## 8. Independent update loop stops mattering once detached view closes
Original _detached_update_loop doc:
Loop kiểm tra cửa sổ tách rời: rebuild nếu danh sách game thay đổi.
Độc lập với tab Start hiển thị hay không.

Once detached resources are closed, the detached-view lifecycle must no longer present/update those overlay items.

## 9. Distinction from C16
C16 is Đóng hết and is the task that closes actual game windows.

C13 must therefore preserve this separation:
- Đóng xem → close preview/view resources;
- Đóng hết → close game HWNDs/process-related game windows.
