## Main findings
- Dồn has one shared Farm session ownership model for both roles: global _farming, per-account _farming_acc, _farm_threads, per-row _stopping_play and row._gen.
- Role is classified when a full session is started. A selected receiver starts the receiver runner / don_logic.recv_cycle; a normal account starts _farm_cycle with a donor callback.
- Receiver and donor are therefore different workers under the same play/stop membership. _farm_acc is only the internal StartAutoFight primitive and is not the full role/session FSM.
- Receiver start also starts receiver donated-gold tracking and the receiver death/disconnect session guards. recv_cycle is sell -> return to receive point -> ready -> wait donated/abort/dead-donor -> repeat.
- Donor _farm_cycle remains the normal Train loop. don_callback replaces the normal return-town/sell leg with Dồn; after that callback, the ordinary return-to-train/fight leg remains.
- Per-row donor callback exposes Về dồn and Đang dồn. The global Bắt đầu path additionally has an explicit pre-stage/wait surface at the shared Dồn point using don_mark_waiting / Chờ dồn before ready selection.
- Receiver GUI lifecycle is projected through Bán đồ / Tới nơi nhận / Sẵn sàng nhận / Chuẩn bị nhận / Đang nhận; _on_recv_phase exactly maps transaction start -> Đang nhận and done -> Sẵn sàng nhận only if still Đang nhận.
- Donor normal resting/training projection returns to Đi train -> Đang train after Dồn/failure/no-ready paths; full-bag/filter/death/heal states remain the already-frozen subflows.
- Stop is cooperative. _stop_acc stops the game character and clears the per-account Farm flag; _stopping_play prevents overlapping restart while the old worker drains; _wait_farm_stop joins the requested Farm workers.
- Stopping one account while others remain leaves global Dồn Farm running. Stopping the last active account enters the global drain/reset workflow.
- row._gen is the stale-worker barrier. Session workers capture gen_snap; old buff/monitor work exits after stop/start generation change. _restore_play_button refuses to overwrite a newer run when gen no longer matches.
- Role selection changes do not dynamically replace the worker already running. _on_receiver_selected only restyles/reorders. A receiver deselected while its recv_cycle is alive can subsequently hit the explicit “not in receiver list” guard instead of turning into a donor; an already-running donor selected as receiver does not gain a recv_cycle/ready registration until a later stop/start.
- Exact _gen increment/mutation statement ordering remains source-insufficient and is not invented.
- Runtime log has no correlated Dồn lifecycle trace, so thread timing and state-label timing remain runtime-required.
