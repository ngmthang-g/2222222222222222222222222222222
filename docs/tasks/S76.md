## Source-grounded input and localized defect
Continued LIVE PLAN.md / STATE.md S75 NEXT_ACTION and inspected C15 original documented `refresh_window_preview_list`, `_clear_window_preview_list`, `_destroy_window_preview_item`. Original C15 refresh **must** deregister native DWM previews, destroy destination HWNDs and all Tk preview frames, then rebuild from the current game HWND/cache list while retaining C17 HWND-keyed manual ordering. Existing src/start_tab.py already has functional C15 "Làm mới", real Win32 DWM and an S09 immutable cache consumer; therefore none of this was rewritten from scratch.

Found reproducible local failure: `TLMStartTab._drop_previews()` invoked native controller.shutdown() *before* unlinking the controller; if a DWM unregister threw, `_clear_window_preview_list()` exited **before destroying the remaining Tk frames**. The explicit full refresh then escaped with Tk callback error and could leave a stale DWM controller and ghost frames. S71 had made `ReadOnlyDwmPreviews.clear()` attempt all native DWM slots despite native errors, but the C15 Start UI owner had not gained corresponding full-frame cleanup and safety latch. Exact original Nuitka exception handling remains UNKNOWN; the S76 behavior is an explicit fail-closed safety fix.

## Scoped source implementation
**ONLY existing** src/start_tab.py changed (commit a396faa605cef71ad7169b7c6f3aab09ba72e12c):
- `_drop_previews`: cancels pending 60ms Tk callback as before, unlinks DWM controller **before** native shutdown. On a native exception it sets `_preview_cleanup_faulted` and rethrows, preserving error evidence.
- `_clear_window_preview_list`: attempts native DWM teardown first; ALWAYS attempts destruction of **every** old Tk tile frame even if DWM shutdown or an earlier Tk frame destruction throws. Clears cached old items/observed HWNDs; reports the first error and latches native-preview fault, does not mark refresh successful.
- `refresh_window_preview_list`: after teardown error returns False, shows explicit "Preview lỗi: giải phóng DWM chưa xác minh" and refuses to recreate tiles/DWM. Cache error path remains fail-closed even when secondary native cleanup errors occur. Successful original-backed C15 refresh and saved C17 order are unchanged.
- While faulted, `_present_cached_snapshot`, `_schedule_preview` and `_refresh_dwm` refuse to create new native DWM registrations for that Start owner lifetime. Read-only HWND table updates still allowed. No user-facing new control, game input, proxy, C14 tiles, signed grant bypass, or guessed new timer/geometry. No source outside Start modified.
