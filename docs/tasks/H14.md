## 1. There are two different Farm state layers

The frozen FarmTab initializes both:
- `_farming`
- `_farming_acc`
and a separate worker collection:
- `_farm_threads`.

H12 already locked `_farming_acc` as the authoritative per-account membership used by play-button state and session guards.

H14 locks the separation:

- `_farming_acc` = which HWND/account sessions are currently intended to remain in automatic Farm;
- `_farming` = global Farm mode / large-button state;
- `_farm_threads` = worker-lifecycle collection used by the stop/wait path.

Do not collapse these into one boolean. During partial stop or thread drain, per-account membership and thread liveness are intentionally not the same thing.

Exact assignment statements for `_farming` remain stronger-decompilation UNKNOWN, but the transition invariants below are directly documented.

row Farm
→ request cooperative session stop
→ row enters stopping sentinel `…`

→ global stays running.

global running
→ target only accounts currently Farm
→ request cooperative stops
→ wait for targeted Farm workers
→ no remaining accounts
→ final green `Bắt đầu` / enabled.
