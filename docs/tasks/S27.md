## 2. New source: `src/login_window_handoff.py`
- `wait_for_pid_window(pid, ..., backend, cancel, timeout_seconds, poll_seconds)`: bounded **25s maximum** wall-clock handoff with default `0.1s` local poll policy; accepts a caller-supplied external real PID; uses S26's `find_main_window_by_pid` and its existing S08 native Win32 backend, never creates game processes. Timeout can be shortened for tests but cannot exceed 25 seconds. `timeout_seconds=0` explicitly does a single snapshot.
- Returns immutable `WindowHandoffResult(pid, hwnd, code, elapsed_seconds, scans)` with `FOUND/TIMEOUT/CANCELLED/INVALID_PID/BACKEND_UNAVAILABLE/ENUMERATION_FAILED`, never returns an invented HWND. Cancellation is evaluated before and after each scan and can interrupt waits via `Event.wait`.
- Rechecks `IsWindow`, `IsWindowVisible` and PID immediately at the handoff boundary even after S26 final selection. Rejects HWND discovered after the allotted positive deadline; a single native Win32 enumeration itself is non-interruptible, so absolute wall time can slightly overshoot if WinAPI is slow. This limitation is explicitly documented, **no false strict realtime claim**.
- `SerializedPidWindowHandoff` shares a `threading.Lock` to serialize **handoff waits only**; each caller's budget includes waiting for the lock, with cancellation while queued, and lock release even after errors. This is a bounded S27 mechanism, **not** the original hidden `_launch_lock`/actual game launching.
- `DEFAULT_POLL_SECONDS=0.1`, `_LOCK_POLL_SECONDS=0.05`, tie/locking details and status names are S27 local policy, not recovered original microinstructions.
