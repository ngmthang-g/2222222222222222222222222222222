## 1. Global Party action button

Therefore the bottom control is a real persistent run/stop lifecycle, not a one-shot command.

## 2. Global start validation and transition to running state

The `_toggle_run` constant block contains:
- `get_groups_data`
- local `jobs`
- local `sec`
- exact log `[Party] Chưa có nhóm nào chọn acc`
- exact log fragments `[Party] Bắt đầu <N> cụm — <M> acc`
- `clear`
- visible running text `Dừng lại`
- red `#f44336`

Verified lifecycle:
1. collect configured group jobs;
2. if no group has selected accounts, log and do not launch;
3. clear the shared/global cancel event for a new run;
4. switch the bottom button to the red `Dừng lại` state;
5. launch the global Party worker path.

The exact source-level statement ordering around setting `_running=True` vs button recolor/thread start is not exposed strongly enough to reproduce instruction-for-instruction and remains a micro-order UNKNOWN.

## 3. Global stop transition

The same global block contains the stopping UI:

Immediately after the global toggle constants, `PartyTab.stop` has exact documentation:

This verifies a distinct stop phase:

The exact native ordering of `_cancel.set()`, child-cancel fan-out, `_running` assignment and lock release inside `stop()` is not directly source-visible and is kept explicit rather than guessed.

## 4. Global cancellation model

Constructor state proves:
- one global `_cancel` Event;
- one `_run_lock`;
- one collection `_run_cancels`.

Party's own summary explicitly states:

`Nút Bắt đầu: chạy SONG SONG các nhóm (mỗi cụm 1 thread, cancel riêng từng cụm)`

The `_run_worker` constant block additionally contains:
- local `own_cancels`
- local `threads`
- `is_alive`
- `join`
- `timeout`
- `_after_party_action`
- `_reset_run_button`.

Therefore global execution is:
- one aggregate Party run;
- each cluster gets its own cancellation Event/thread;
- the aggregate worker waits for cluster workers;
- once they have settled, post-party action is considered;
- global UI reset occurs once.

## 5. Global clusters really run concurrently

Exact `_run_worker` documentation:

`Chạy SONG SONG các cụm: mỗi cụm 1 thread (_run_one_group), xong
         hết mới làm hành động Sau khi party + reset UI (1 lần duy nhất).`

This locks:
- parallelism unit = one thread per Party cluster;
- per-cluster body = `_run_one_group`;
- aggregate completion waits for all cluster workers;
- post-party action is an aggregate once-only phase, not once per cluster;
- global reset is once-only after aggregate completion.

G09 does not yet decode the internal B0→B3 team protocol inside `_run_one_group`.

## 6. Interruptible sleep uses per-cluster cancel with global fallback

Exact `_sleep` documentation:

`Sleep ngắt được: True nếu bị hủy giữa chừng (cancel riêng từng cụm,
         mặc định cancel chung).`

This is important for lifecycle reconstruction:
- action waits are cancellation-aware;
- a cluster worker can receive its own Event;
- when no per-cluster Event is supplied, the global Party cancel Event is the default.

Do not replace these waits with unconditional `time.sleep` in later reconstruction.

## 7. Per-group action button

Each group cluster has:
- visible action label prefix `▶ Tạo nhóm `
- callback `_run_single_cluster`
- state fields `join_btn`, `join_cancel`, `join_running`.

The `_run_single_cluster` block contains:
- permission-with-limit check for Party;
- exact log suffix `: đang chạy rồi`;
- `_group_members`;
- exact validation `: cần ít nhất 2 acc`;
- running UI text `⏳ Đang vào...`;
- state `disabled`;
- worker target `_run_single_worker`.

So a single-cluster run:
1. checks Party permission/account limit;
2. refuses a duplicate invocation while that cluster's `join_running` state is already active;
3. requires at least two selected account names;
4. disables its own cluster button and changes the visible text to `⏳ Đang vào...`;
5. launches its own background worker.

## 8. Per-group worker is intentionally independent of the global button

Exact original documentation for `_run_single_cluster`:

`Nút 'Vào nhóm' cuối mỗi frame cụm: chỉ chạy 1 mình cụm đó.

         Độc lập với nút Bắt đầu chung (chạy thread riêng, cancel riêng),
         nhiều nhóm có thể gọi song song.`

The visible current UI label is `▶ Tạo nhóm N`; the doc's “Vào nhóm” is internal/legacy wording for that per-cluster action.

This proves:
- per-group action uses a separate thread;
- it uses a separate cancel object;
- different per-group runs can execute in parallel;
- the per-group action is architecturally independent from the global Bắt đầu worker.
